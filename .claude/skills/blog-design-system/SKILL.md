# 블로그 디자인 시스템

리뉴얼 때 쓰던 시각 기준 파일(`design-reference.html`)은 구현이 끝나 **삭제했다.**
이제 기준은 **구현된 화면 자체**다 — 홈(`/`)과 글 상세를 dev 서버로 열어 대조한다.
원래의 디자인 의도와 결정 배경은 `apps/blog/web/design/redesign-decisions.md`에
남아 있고, 수치는 아래 항목들이 단일 출처다.

> 그 문서는 **왜 그렇게 정했는지**만 답한다. 값은 만들면서 바뀐 것이 있으니
> (포인트색, 배지 라운드, 다이어그램 라벨 크기) 수치의 근거로 쓰지 말 것.

## 컬러 토큰

색은 전부 `packages/@blog/preset/src/blog-preset.ts`의 semanticTokens로 정의돼
라이트/다크가 자동 전환된다. **컴포넌트에서 hex를 직접 쓰지 않는다.**

값 자체는 같은 파일의 `blogColors` 상수에 있고 프리셋이 그것을 쓴다. 이 상수는
Panda가 주는 `defineSemanticTokens.colors()`로 감싸 시맨틱 토큰 계약을 검증받는다 —
조건 키 오타나 잘못된 값 모양이 이 파일에서 잡히고, 헬퍼가 제네릭이라 토큰 이름은
리터럴로 남는다.

**CSS 변수를 못 읽는 렌더러**(satori/sharp — 블로그 OG 카드가 그렇다)는 리터럴 색이
필요한데, 그때도 hex를 옮겨 적지 말고 같은 파일이 내보내는 `themeColor('dark', 'ink.950')`으로
뽑는다. 이름이 `blogColors`의 키로 좁혀져 있어 오타나 토큰 이름 변경이 컴파일
에러가 된다. 예전에 OG 카드가 hex 사본을 들고 있을 때는 팔레트를 바꿔도 카드만 옛
색으로 남았고, 렌더는 성공하므로 아무도 알려주지 않았다(실제로 pill 보더 알파가
0.4/0.42로 갈려 있었다).

OG 카드의 **브랜드 cyan**(`#67E8F9`, pill 보더는 그 42%)만 토큰이 아니다 — 같은 파일이
내보내는 상수 `ogBrand`이고 `content.config.mts`가 카드 팔레트로 넘긴다. 화면의 포인트색이
잉크로 옮겨 간 뒤에도 카드 디자인은 바꾸지 않아서다. 토큰이 아니므로 CSS 변수가 나가지 않고,
컴포넌트에서 색 이름으로 쓰면 strictTokens에 걸린다. 카드가 썸네일인 글은 홈·목록에서 cyan이
보인다(공개 글 대부분이 생성 카드를 썸네일로 쓴다).

| 레퍼런스 CSS 변수                     | 토큰                             | 라이트 / 다크                               |
| :------------------------------------ | :------------------------------- | :------------------------------------------ |
| `--bg`                                | `paper.50`                       | `#FFFFFF` / `#0B0D10`                       |
| `--bg-sub`                            | `paper.100`                      | `#F7F7F5` / `#14171C`                       |
| `--page` ⚠️                           | `paper.200`                      | `#EDEDEA` / `#1B1F26`                       |
| `--fg`                                | `ink.950`                        | `#1A1A1A` / `#E6E8EB`                       |
| `--fg-sub`                            | `ink.600`                        | `#6B7280` / `#8B919A`                       |
| `--fg-sub` (서브 서피스 위 12px 메타) | `ink.500`                        | `#656C77` / `#8B919A`                       |
| `--border`                            | `ink.border`                     | `rgba(0,0,0,.10)` / `rgba(255,255,255,.12)` |
| `--danger`                            | `danger.text` / `danger.border`  | `#C81E1E`·`#DC2626` / `#F09595`             |
| `--success`                           | `moss.600` (텍스트는 `moss.700`) | `#16A34A` / `#97C459`                       |
| `--warn-bg` / `--warn-fg`             | `warn.bg` / `warn.text`          | `#FAEEDA`·`#854F0B` / `#3A2A10`·`#FAC775`   |

> ⚠️ **`paper.200` 다크만 시안(`#060809`)을 따르지 않는다.** 시안의 `--page`는 목업
> 카드 **뒤쪽 바깥 배경**이라 다크에서 `--bg`보다 더 어둡다. 실제 사이트엔 그 바깥
> 배경이 없고 `paper.200`은 인라인 코드·콜아웃처럼 지면에서 **한 단계 떠 있는**
> 서피스라, 시안 값을 쓰면 코드 배경이 본문보다 어두워져 파여 보인다.

### surface — 앱 화면(admin)의 바닥과 카드

admin은 지면 한 장이 아니라 **바닥 위에 카드**를 놓는 앱 화면이다(승인 admin 목업, Astryx body·card).
카드는 두 테마 모두 바닥보다 한 단계 밝다 — paper 단계는 라이트에서 내려가고(50이 가장 밝다) 다크에서
올라가므로(50이 가장 어둡다) 한 이름으로는 이 쌍이 안 나와, 같은 상수에서 테마마다 단계를 고른 토큰을
둔다. 공개 페이지는 쓰지 않는다.

| 토큰             | 값 (라이트 / 다크)                               | 자리                                      |
| :--------------- | :----------------------------------------------- | :---------------------------------------- |
| `surface.base`   | `paper.100` · `paper.50` — `#F7F7F5` / `#0B0D10` | admin 바닥 · 관리자 바(80% + 흐림)        |
| `surface.raised` | `paper.50` · `paper.100` — `#FFFFFF` / `#14171C` | 카드 · 표 카드 · 글 통계 패널·시트 · 입력 |

- 카드 위 hover 면은 `ink.50`(`#F7F7F5` / `#1B1F26`) — `paper.100`은 다크 카드와 같은 색이라 보이지 않는다.
  ghost 아이콘 버튼의 hover(`paper.100`)도 같은 이유로 admin에서는 `paper.200`으로 올린다(`panelIconButton`)
- 고른 줄은 `accent.muted`(검색 선택 행과 같은 틴트)에 왼쪽 끝 2px 잉크(`accent.solid`) 막대 — 다크에서 틴트가
  hover(`ink.50`)와 한 단계밖에 차이 나지 않아 막대가 고른 줄을 세운다(그림자 아님)

### accent — 따로 고른 포인트색이 없다

`accent.*`는 본문 잉크·지면과 **같은 상수**(`blogColors` 앞의 `INK_950`·`INK_800`·`PAPER_50`)에서
파생한다. 값을 옮겨 온 Astryx docsite 테마(MIT)가 accent 토큰 전부를 그 테마의 primary 텍스트
잉크로 돌리는 구조를 따랐다. 대비는 지면(`paper.50`) 기준이다.

| 토큰                | 값 (라이트 / 다크)                 | 자리                                                                    | 대비                                                  |
| :------------------ | :--------------------------------- | :---------------------------------------------------------------------- | :---------------------------------------------------- |
| `accent.solid`      | `ink.950` — `#1A1A1A` / `#E6E8EB`  | 링크 · 현재 위치 표식 · 주 버튼 면 · 다이어그램 핵심 경로 · 초점 링     | 17.40 / 15.85                                         |
| `accent.muted`      | `ink.950` 8% / 14%                 | 틴트 — 시리즈 배지 · 검색 선택 행·검색어 · tip 콜아웃 · 다이어그램 노드 | 합성 `#EDEDED` / `#2A2C2F`, 그 위 solid 14.87 / 11.41 |
| `accent.onSolid`    | `paper.50` — `#FFFFFF` / `#0B0D10` | solid 면 위 글자(주 버튼 · 상태 배지 · 미리보기 띠)                     | 17.40 / 15.85 (흰 글자로 두면 다크 1.23)              |
| `accent.solidHover` | `ink.800` — `#3A3D42` / `#C2C7CE`  | 주 버튼 hover 면                                                        | onSolid 대비 10.90 / 11.45                            |
| `selection.bg`      | `ink.950` 18% / 22%를 지면에 합성  | 드래그 선택 · 문장 공유 링크 강조(`::target-text`)                      | `#D6D6D6` / `#3B3D40`, 지면 대비 1.45 / 1.79          |

- **`accent.muted` 위 보조 글자는 `ink.700` 이상이다.** 메타 톤 `ink.500`은 그 틴트 위에서 다크
  4.41:1로 AA를 놓친다(`ink.700` 6.46 / 6.11). 검색 선택 행의 메타 줄과 다이어그램 강조 노드의 부제
  (`ink.600`이면 4.13 / 4.41)가 그 자리다
- 제목 계열(홈 히어로 이름 · 카드 제목 · 글 제목 · 본문 h2)은 **`ink.950`**이다 — accent가 아니다.
  제목은 primary 텍스트이고, 본문 h2와 h3는 크기(20/18)·여백으로만 갈린다
- admin 차트의 데이터 색(선·막대·점)과 오늘 조회수 강조는 accent가 아니라 admin 전용 `spot.600`이다.
  잉크로 칠하면 축·글자와 갈리지 않는다

### 색으로 갈리지 않는 자리는 이렇게 가른다

링크 잉크와 본문(`ink.900`)의 대비는 1.15 / 1.16:1이다 — 색은 단서가 아니다.

| 자리                                     | 수단                                                                                                                          |
| :--------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------- |
| 문장 속 링크(본문 · 정책 · 빈 상태 문장) | 평소 1px 밑줄, hover 2px(`src/components/inlineLink.ts`). 굵기·배경·보더 hover는 쓰지 않는다                                  |
| 독립 링크 · 목록 제목                    | hover 밑줄                                                                                                                    |
| 글 카드 · 썸네일 행(홈)                  | hover에 커버 위 `accent.muted` 틴트. 제목 밑줄은 없다(아래 "카드")                                                            |
| 헤더 내비 현재 위치                      | `accent.solid` + semibold(비활성 `ink.700`과 2.30 / 1.87:1) + 라벨 아래 16×2 막대                                             |
| 차례 현재 절 · 코드 탭                   | `accent.solid` 한 이름(아래 굵기 규칙)                                                                                        |
| admin 세그먼트(집계 기간·정렬 기준)      | 선택 항목은 카드 면(`surface.raised`) + 진한 hairline(`ink.borderStrong`) + semibold. 면은 고른 칸으로 미끄러지는 표식 하나다 |
| 시리즈 배지 · 대화 말풍선(나)            | `accent.muted` 면 + `accent.solid` 글자(`seriesBadge`)                                                                        |
| 태그 배지(글 목록 카드 · 활성 필터)      | `paper.200` 면 + `ink.950` 글자(`tagBadge`, Astryx Badge neutral)                                                             |
| tip 대 info 콜아웃                       | 면은 1.07 / 1.22:1로 거의 같다 — 불투명 잉크 보더(info는 알파 28% / 32%)와 글리프                                             |
| 다이어그램 · mermaid 강조 노드           | 잉크 스트로크 대 회색 보더                                                                                                    |
| 검색어 강조(`<mark>`)                    | `accent.muted` 면 + semibold — 면은 행 배경과 1.17 / 1.39:1이고 제목 줄은 제목도 같은 잉크다                                  |

- 현재 위치에 굵기를 더하는 건 이미 쓰던 자리(헤더 내비 · 모바일 목차)뿐이다 — 데스크톱 차례와 코드 탭은
  굵기를 바꾸면 줄 바꿈·탭 폭이 바뀌어 아래 항목이 밀린다

axe `link-in-text-block`은 밑줄·굵기·보더 차이를 구분으로 인정한다. 그래서 문장 속 링크에 굵기를
남기면 밑줄이 빠져도 검사가 통과한다 — 굵기 대신 밑줄을 쓰는 이유다. hover와 block 링크, 부모와
같은 색인 링크는 axe가 보지 않는다.

> **포인트색 이력: 틸 → cyan → 잉크.** 처음엔 틸(`#1D9E75`/`#5DCAA5`)이었다가 다크 시인성(지면 위
> 밝은 톤이라야 읽힌다)과 의미색과의 거리(틸은 success 그린과 색상각이 가까웠다) 때문에 cyan
> (`#0891B2`/`#67E8F9`)으로 옮겼고, cyan은 라이트 AA 때문에 용도별 여섯 단계(선·글자·제목·배지·
> 틴트·밑줄)로 갈려 있었다. 2026-10에 Astryx docsite 테마를 들이며 잉크로 옮겼다 — 단계가 넷이 되고,
> 라이트의 "제목이 본문보다 흐린" 문제(그래서 제목 전용 진한 톤이 따로 있었다)도 사라졌다. cyan은
> OG 카드의 `ogBrand`로만 남았다.

**Astryx와 일부러 다르게 간 곳**(색)

- **잉크 값은 Astryx의 PRIMARY가 아니라 이 팔레트의 `ink.950`이다.** 구조(accent = 그 테마의 primary
  텍스트)만 옮겼다
- **`accent.solidHover`를 새로 뒀다.** Astryx 버튼 hover는 면 위에 그라데이션 레이어를 얹지만
  그라데이션은 금지라, hover 면 색 하나(`ink.800`)로 바꾼다
- **구문 강조 keyword를 accent에 묶지 않는다.** Astryx 코드 테마는 keyword를 accent로 칠하지만 `code.*`는
  본문 팔레트와 독립이다(아래 "코드 블록" — 코드 선택색 `code.selection`도 전역 `selection.bg`를 따르지 않는다)
- **admin 차트는 Astryx 데이터 블루가 아니라 `spot.600`이다** — 새 색 토큰을 들이지 않고 기존 admin 보조
  강조색을 쓴다

## 타이포그래피

- 본문/UI: `fontFamily: 'sans'` (Pretendard Variable)
- **메타 정보는 `fontFamily: 'mono'`** (JetBrains Mono) — 날짜, 읽기 시간, 조회수,
  태그, 코드, 로고, 오픈소스 프로젝트 칩. "측정하는 엔지니어" 무드의 핵심이다.
  승인 목업의 카드 메타는 sans지만 따르지 않았다 — Astryx 테마에 mono가 연결되지
  않은 부작용이다
- 단, **시리즈 배지는 sans**다. `시리즈 · Turborepo 인프라 3/3` 처럼 안에 숫자가
  있어도 본문 성격의 라벨이고, 레퍼런스 `.badge`도 `font-family`를 지정하지 않아
  sans로 렌더된다. 글 상세·`/series` 두 곳이 모두 sans로 맞춰져 있으니
  한 곳만 mono로 바꾸지 말 것 (숫자가 있다고 기계적으로 mono를 적용하지 않는다).
  오픈소스 줄의 합계 칩(`58+ merged`)도 같은 이유로 sans다
- 세리프 금지. `serif` 토큰은 sans로 매핑돼 있어 실수로 써도 세리프가 나오지 않는다

### 글자 역할(textStyles)

크기·행간·굵기는 **역할 이름 하나**로 고른다 — `css({ textStyle: 'h1' })`. 이름은 Astryx 코어 타이포
스케일(MIT)의 역할이고 값은 승인 목업의 수치다. 단일 출처는 `blog-preset.ts`의 `textStyles`(주석에 같은
표가 있다). preset-panda의 textStyles(`xs`~`9xl`)는 블로그 설정이 빼서 이 열셋이 전부다.

| 역할         | px    | 굵기 | 자리                                      |
| :----------- | :---- | :--- | :---------------------------------------- |
| `display1`   | 42/52 | 600  | 페이지 제목 — 홈 이름 · 글 목록 · 글 상세 |
| `display2`   | 35/44 | 600  | 홈 섹션 제목(최근 글 · 지난 글)           |
| `display3`   | 29/36 | 600  | 홈 오픈소스 섹션 제목                     |
| `h1`         | 24/32 | 600  | 홈 쇼케이스 카드 제목                     |
| `h2`         | 20/28 | 600  | 본문 `##`                                 |
| `h3`         | 17/24 | 600  | 카드·행 제목 · 본문 `###`·`####`          |
| `h4`         | 14/20 | 600  | 본문 표 머리                              |
| `large`      | 20/32 | 400  | 리드 문단 — 홈 소개 · 글 상세 dek         |
| `prose`      | 17/28 | 400  | 글 본문                                   |
| `bodyLarge`  | 17/24 | 400  | 홈 쇼케이스 카드 발췌                     |
| `body`       | 14/20 | 400  | UI 기본 글자 · 카드 발췌                  |
| `label`      | 14/20 | 500  | 버튼 · 헤더 내비                          |
| `supporting` | 12/20 | 400  | 메타 · 푸터 · 보조 설명                   |

- **단위는 rem이다**(표의 px는 루트 16px일 때) — 브라우저 글자 크기 설정을 따른다
- **자간은 두지 않는다.** Astryx는 전부 normal이고, 한글에 음수 자간을 주면 받침이 붙어 보인다
- 굵기·색만 다른 자리는 같은 `css()`에 `fontWeight`를 더한다 — textStyle은 utilities 레이어 안의
  `compositions` 하위 레이어라 같은 요소의 유틸리티가 이긴다(헤더 내비 현재 위치 = `label` + semibold)
- 쓰는 곳이 생긴 역할만 CSS로 나간다(Panda가 사용처에서 뽑는다) — 정의만 있는 역할은 무게가 없다
- 메타(mono) 글자는 역할 밖이다 — 날짜·태그·워드마크는 `fontFamily: 'mono'`와 크기를 직접 준다
- 글 본문(`PostBody`)은 `prose` 17/28 `ink.950`이고 블록 간격을 마진 상쇄에 맡긴다 — 문단·리스트 12, 코드·표·
  인용 16, `##` 위 32 아래 12, 첫 블록 위·마지막 블록 아래는 0. `###`·`####`는 본문과 같은 17px이라 굵기와 위 여백(24·16)이
  가르고 `####`만 `ink.700`이다. 인용은 2px `ink.borderStrong` 막대에 `ink.700`. 표는 `role="region"` 래퍼가 보더·`element`
  라운드·`overflow-x: auto`·`tabIndex`를 쥐고(표 자신은 보더 없음, 칸 사이는 세로선과 행 사이 가로선뿐), 머리 칸은
  `h4` `ink.700`이다 — 래퍼를 `overflow: hidden`으로 두면 넓은 표가 잘린다
- 글 목록 뷰 토글 칸은 13px — 역할 밖 예외다(`label`에 `fontSize: '[13px]'`, Astryx ToggleButton sm)

## 형태

**라운드(radii)는 Astryx docsite 테마(MIT)의 스케일이다** — 코어 기본값(4/8/12/28)에 4px씩
더한 값이고 `none`·`full`은 코어 그대로다. 이름은 크기가 아니라 **자리**라, 요소가 어느 자리인지로
고른다. **이 여섯이 전부다** — 블로그 설정이 preset-panda의 radii를 빼므로 다른 이름은
strictTokens에 걸린다.

| 토큰        | 값     | 자리                                                                                                   |
| :---------- | :----- | :----------------------------------------------------------------------------------------------------- |
| `none`      | 0      | 모바일 전체화면 검색 다이얼로그                                                                        |
| `inner`     | 8px    | 인라인 코드 · 검색어 mark · 세그먼트 안쪽 탭 · 스켈레톤 줄 · 초점 링                                   |
| `element`   | 12px   | 입력 · 검색창 · 헤더 내비 항목 · 세그먼트 그룹 · 코드 블록(코드 탭) · 파일 트리 · 이미지               |
| `container` | 16px   | 카드·카드 커버 · 패널 · 콜아웃 · `details` · mermaid 상자 · 바텀시트 윗모서리 · 다이얼로그 · 차트 툴팁 |
| `page`      | 32px   | 대화 말풍선(`<dialogue>`)만                                                                            |
| `full`      | 9999px | 버튼(아이콘 버튼·FAB 포함) · 배지(태그·시리즈·상태·개수) · 칩(시리즈·오픈소스) · 원형 · 스크롤바       |

- **버튼은 `full`이다.** Astryx 코어는 버튼을 `element`로 두지만 docsite 테마가 모든 버튼을
  pill로 덮는다. 복사 아이콘 버튼·헤더 검색 버튼·테마 전환 버튼도 버튼이라 같다
- **태그·시리즈·상태 배지도 `full`이다**(Astryx Badge). 예전의 "배지는 6px, pill 아님" 규칙은
  이 스케일로 옮기며 폐기했다
- **초점 링은 `inner`** — globalCss의 `:focus-visible`(base 레이어)이 준다. 자기 라운드가 있는
  요소는 utilities 레이어라 그 라운드를 지킨다. 상태를 숨긴 네이티브 radio(칩·토글 칸)는 링을 바로
  뒤 형제인 면에 그린다(`input.peer[type=radio]:focus-visible + *`) — 값은 같은 상수 `FOCUS_RING`이다. 본문 표·자동 배치 그림의 가로 스크롤 래퍼도 초점
  링 때문에 라운드를 갖는 자리라 `inner`다
- **Astryx와 일부러 다르게 간 곳** — 말풍선은 Astryx의 chat 전용 28px 대신 `page`(Astryx 문서는
  page를 페이지 단위 컨테이너용으로 적는다). 안쪽 요소의 동심 라운드(바깥 − 패딩)는 계산하지 않고
  토큰 하나를 고른다
- **`container` 안에 든 상자는 한 단계 아래인 `element`다** — 카드 안의 경고 배너, 펼친 패널 안의
  통계 타일처럼 따로 놓이면 `container`인 상자라도, 안에 들면 바깥과 같거나 큰 라운드를 두지 않는다.
  최상위에 나란히 놓인 타일은 그대로 `container`다
- **건너뛰기 링크는 `element`** — 버튼 모양 링크(공용 액션 버튼 스타일, about의 CTA)는 버튼이라
  `full`이다. 건너뛰기 링크는 Astryx AppShell에서도 Button이 아닌 맨 앵커라(자기 라운드 없음) docsite의
  버튼 pill 덮어쓰기 밖이고, 보더 있는 한 줄 상자라 입력과 같은 자리에 둔다
- **Panda 밖의 숫자는 이 스케일과 무관하다** — 다이어그램 노드 `rx`(SVG), Recharts 막대 `radius`,
  코드 하이라이터의 `customStyle.borderRadius: 0`(바깥 상자가 자른다)은 그대로 둔다

그 밖의 형태:

- 보더: `borderWidths.hairline`(1px) 단일 소스. **지면 위의 위계(카드·패널·행·hover)는 보더로
  표현한다** — 그림자는 아래 "그림자" 절의 떠 있는 표면에만 쓴다
- **그라데이션 · 글로우 금지**
- Panda는 `strictTokens: true`다. 토큰 밖 값은 `fontSize: '[12px]'`, `maxH: '[70vh]'`처럼
  대괄호로 이스케이프해 "여긴 의도적으로 토큰을 벗어난다"를 코드에 남긴다. 단 색·라운드·보더
  굵기·그림자·모션(시간·곡선·애니메이션, `transition` 단축 속성)은 이스케이프도 lint
  (`prefer-token`, `transition`은 `no-restricted-syntax`)가 막는다 — 맞는 토큰이 없으면 프리셋에 더한다

## 그림자 — 떠 있는 표면에만

값은 Astryx 코어(MIT)의 `--shadow-med`·`--shadow-high`를 그대로 옮겼다(docsite 테마는 그림자를
덮어쓰지 않는다). 코어의 `light-dark()` 쌍을 라이트/다크로 나눴다. **이 둘이 전부다** — 블로그
설정이 preset-panda의 그림자를 빼서 다른 이름은 strictTokens에, 대괄호 이스케이프는
`prefer-token`에 걸린다.

값(라이트·다크 쌍)은 `packages/@blog/preset/src/blog-preset.ts`의 `shadows.overlay.med`·`shadows.overlay.high`가
단일 출처다. 어느 면에 어느 단계를 쓰는지는 아래 표면 표가 정한다.

**판정 — 넷을 모두 만족하는 면에만 그림자를 단다.**

1. 흐름 밖(Portal·absolute·fixed)에 뜬다
2. 아래 콘텐츠를 가린다 — 단 화면 전체를 덮는 면은 그림자가 떨어질 가장자리가 없어 제외한다
3. 닫기·Escape·포인터 이탈 중 하나로 사라진다
4. 반전(잉크) 면이 아니다

lint는 그림자 **값**만 막는다. 어느 면에 붙였는지는 이 판정으로 리뷰가 본다.

| 표면                                | 그림자              | 보더                                        | 라운드                 |
| :---------------------------------- | :------------------ | :------------------------------------------ | :--------------------- |
| 검색 다이얼로그 — md 이상 센터 모달 | `overlay.high`      | hairline                                    | `container`            |
| 검색 다이얼로그 — 모바일 전체화면   | 없음(판정 2의 예외) | 없음                                        | `none`                 |
| 목차 바텀시트                       | `overlay.high`      | hairline(위)                                | 윗모서리 `container`   |
| admin 차트 툴팁                     | `overlay.med`       | hairline                                    | `container`            |
| admin 글 통계 시트 — lg 미만        | `overlay.high`      | hairline(왼쪽 — sm 미만은 전폭이라 화면 끝) | `none`(화면 끝에 붙음) |

- **차트 툴팁은 공용 컴포넌트(`ChartTooltip`·`ChartTooltipFrame`) 하나로 그린다.** Recharts
  `contentStyle` 같은 인라인 style은 Panda 추출 밖이라 토큰 검사가 닿지 않는다. 표면은
  Recharts가 넘기는 `accessibilityLayer`를 필수로 받아, 기본 툴팁이 주던 스크린리더 알림
  (`role="status"`)을 잇는다
- **떠 있어도 그림자가 없는 것** — FAB 둘(목차 열기·맨 위로)은 버튼이라 없다(hairline
  보더로 본문과 분리). 문장 공유 버튼(QuoteLink)은 반전 면이라 지면과 반대 톤이 이미 띄운다.
  스티키 헤더·건너뛰기 링크·미리보기 배너는 닫는 면이 아니다
- 새 오버레이를 만들 때 단계는 Astryx를 따른다 — 다이얼로그·드로어·시트는 high, 토스트·차트
  툴팁은 med, 팝오버·메뉴는 low

**Astryx와 일부러 다르게 간 곳**

- **다이얼로그에 hairline을 남긴다.** Astryx Dialog는 보더가 0이지만, 다크에서 다이얼로그
  면과 dim 아래 지면의 대비가 1.04:1이고 그림자도 어두운 지면 위에서는 거의 보이지 않는다 —
  다크의 경계는 보더가 맡는다. 바텀시트는 Astryx와 같다 — Astryx BottomSheet도 scrim을 향한
  변에 hairline을 두고 high를 준다(다크에서 시트 가장자리가 보이지 않아 보더를 더했다). 목차
  시트는 화면 폭 전체라 좌우 변이 화면 끝에 붙고, 위 변에만 보더를 둔다
- **세그먼트 컨트롤(admin 집계 기간·정렬 기준)의 선택 항목에 그림자가 없다.** Astryx는 low를 주지만 흐름
  안의 요소라 판정 1에 걸린다
- **FAB에 그림자가 없다.** Astryx의 FAB 예제(IconButtonFloating 블록)는 아이콘 버튼에
  `elevation="high"`를 준다
- **`overlay.low`는 정의하지 않았다.** 쓰는 면이 없다 — 첫 팝오버·메뉴를 만드는 커밋이 Astryx
  `--shadow-low` 값으로 더한다
- **scrim은 합치지 않았다.** 검색은 `scrim.dialog`, 목차 바텀시트는 `scrim.sheet`다(Astryx는
  `--color-overlay` 하나). 두 값은 테마와 무관하게 어둡다 — 잉크 색(`ink.950`)을 반투명으로 깔면
  다크에서 백드롭이 밝아진다

## 모션

시간과 곡선은 Astryx 코어(MIT)의 모션 토큰을 이름째 옮겼다(docsite 테마는 motion을 덮어쓰지
않는다). 코어의 시간은 아홉 단이고 블로그는 쓰는 넷만 둔다. 블로그 것은 엇갈린 진입의 간격(`stagger`)과
누름의 시간·곡선 세 쌍(`press`·`release`·`spring` — 아래 "인터랙션 상태")이다. **시간은 이 여덟, 곡선은 이
여섯이 전부다** — 블로그 설정이
preset-panda의 durations·easings·animations·keyframes를 빼서 `transitionDuration: 'normal'`·
`animation: 'pulse'`는 strictTokens에, 대괄호 이스케이프는 `prefer-token`에, `transition: '[…]'`는
`no-restricted-syntax`에 걸린다.

| 토큰                  | 값                                        | 쓰는 곳                                                                                                                                                                                |
| :-------------------- | :---------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `durations.fast`      | 175ms                                     | hover·색(누르는 동안의 면 포함)·표식(차례 하이라이트·뷰 토글 면·admin 선택 표식)·떠 있는 버튼의 누름·카드가 들어가는 누름·나가는 페이지·자리를 넘기는 스냅샷(admin `out`·`slideOut`)   |
| `durations.fastMax`   | 230ms                                     | 테마 크로스페이드 · `<details>` 펼침 · 옆에서 들어오는 페이지 · 교체로 들어오는 스냅샷(admin `rise`·`slideIn`, fast 뒤)                                                                |
| `durations.medium`    | 410ms                                     | 바텀시트·시트 스크림 · 들어오는 페이지 · admin 카드 진입                                                                                                                               |
| `durations.mediumMax` | 550ms                                     | 검색 다이얼로그 등장 · 스켈레톤 왕복 · admin 차트·가로 막대 그리기                                                                                                                     |
| `durations.stagger`   | 40ms                                      | 간격 — admin 카드 진입이 순서 × 이 값만큼 늦게 출발한다                                                                                                                                |
| `durations.press`     | 40ms                                      | 누름 진입 — 투명도·크기(카드의 크기·커버 밝기는 fast). `stagger`와 값만 같다(길이와 간격)                                                                                              |
| `durations.release`   | 320ms                                     | 놓음 — 투명도·카드 커버 밝기(크기는 spring)                                                                                                                                            |
| `durations.spring`    | 520ms                                     | 크기의 놓음 — 스프링이 잔차 1% 아래로 가라앉는 길이. `easings.spring`과 짝이다                                                                                                         |
| `easings.standard`    | `cubic-bezier(0.24, 1, 0.4, 1)`           | 기본 — 감속 곡선이라 등장·hover에 맞다                                                                                                                                                 |
| `easings.exit`        | `cubic-bezier(0.3, 0, 0.6, 0.6)`          | 화면 밖으로 나가는 움직임(시트 닫힘·나가는 페이지)                                                                                                                                     |
| `easings.linear`      | `linear`                                  | 거리 없는 퇴장 페이드(시트 스크림 닫힘)·스크롤에 묶인 진행 바·스켈레톤                                                                                                                 |
| `easings.press`       | `cubic-bezier(0, 0, 0.2, 1)`              | 누름 진입 — 감속, 40ms 중 16ms에 거리의 75%                                                                                                                                            |
| `easings.release`     | `cubic-bezier(0.455, 0.03, 0.515, 0.955)` | 놓음 — easeInOutQuad. 출발이 느려 놓은 뒤 80ms에 13%만 돌아온다(옛 fast·standard는 94%) — 짧은 클릭에도 눌린 모양이 남는다                                                             |
| `easings.spring`      | `linear(…)` 33점                          | 크기의 놓음 — SwiftUI `spring(response: 0.35, dampingFraction: 0.5)`를 520ms에 맞춰 뽑았다(오버슈트 16%, 94%에서 놓으면 202ms에 101%). `linear()`를 모르는 브라우저에서는 release 곡선 |

**쓰는 법**

- 색·투명도 hover는 `transition: 'colors' | 'opacity' | 'common'`만 적는다 — 시간·곡선의 기본값
  (fast·standard)은 globalCss가 모든 요소에 토큰으로 준다. 단축 목록에 없는 속성(`clip-path`·
  `block-size`)은 `transitionProperty` + `transitionDuration`·`transitionTimingFunction`
  토큰으로 쓴다. 이 셋은 값을 CSS 변수(`--transition-prop`·`-duration`·`-easing`)로도 내고 단축
  유틸리티가 그 변수를 읽는데, globalCss가 세 변수를 모든 요소에서 다시 정하므로 자손에 새지 않는다
  — 그 블록에서 하나라도 빼면 바깥 요소의 값이 안쪽 hover 전환을 덮는다
- **누름 프리셋을 펼친 요소는 `transition*`을 다시 적지 않는다.** 프리셋의 `pressTransition`(panda.config의
  `PRESS_TRANSITION`)이 속성마다 시간을 나눈 `transition` 한 벌이다 — 색은 위 기본값(fast·standard)을 그대로
  읽고, 투명도·크기는 누를 때 press를, 놓을 때 투명도는 release·크기는 spring을 탄다. 단축 유틸리티를 겹치면 누름 목록에 지고, longhand
  (`transitionDuration` 등)를 겹치면 그 원자가 뒤에 와 누름 시간까지 덮는다. 그래서 같은 요소의 투명도
  hover도 release를 탄다 — 워드마크의 hover 0.7은 들고 날 때 320ms다(놓음과 hover가 같은 상태
  `:hover:not(:active)`에 도착해 가를 선택자가 없다)
- **움직임 줄이기는 토큰이 처리한다.** 시간 토큰이 `prefers-reduced-motion: reduce`에서 0.01ms가
  되므로 컴포넌트에 `@media (prefers-reduced-motion)` 규칙을 따로 두지 않는다. 0이 아니라 0.01ms인
  이유는 `transitionend`가 그대로 오게 하려는 것이다(퇴장이 끝나야 언마운트하는 시트). 무한 반복
  애니메이션은 0.01ms면 깜빡이므로 animations 토큰이 `none`이 된다(`skeleton`). 시간이 아니라 스크롤에
  묶인 애니메이션(글의 진행 바)만 토큰이 끄지 못해 그 자리에서 `_motionReduce`로 끈다
- **`@starting-style`(`_starting`)은 상호작용으로 삽입되는 요소에만** 쓴다. 서버가 그린 요소나
  하이드레이션 직후 모든 페이지에 삽입되는 요소(목차 FAB)에 걸면 하드 로드마다 재생된다
- **목록 진입·스크롤 리빌은 넣지 않는다.** 하드 로드의 모션은 LCP를 늦추고, 스크롤 리빌은 화면
  밖 요소를 투명도 0으로 남겨 런타임 게이트의 가시성 검사에 걸린다. 예외는 admin의 카드 진입 하나다 —
  가드와 데이터를 기다린 뒤에만 그려지는 화면이라 진입이 첫 페인트가 아니라 스켈레톤 다음 장면이고,
  화면 밖 카드도 같은 시간에 끝나는 유한 애니메이션이다(e2e axe 도우미가 끝까지 기다린다)
- **화면 안의 교체(admin)는 React `<ViewTransition>`이다** — 열림·닫힘·교체가 transition(주소 변경·
  `startTransition`)이라 React가 이전 화면의 스냅샷을 걷어 주므로 퇴장 동안 마운트를 붙들 상태가 없다.
  클래스는 무엇이 아니라 어떻게 움직이는지의 이름이다(`src/shared/adminViewTransitions.ts` — `out`·`rise`·
  `slideIn`·`slideOut`·`sheet`·`drawer`·`resize`·`scrim`). 교체는 이전 것이 fast로 걷힌 **뒤에** 새 것이 fastMax로 선다 — 함께 돌리면 exit
  곡선의 느린 출발 때문에 옛 글자가 진한 채 새 글자와 두 겹으로 겹친다. 화면 밖 경계는 React가 움직이지
  않는다(스냅샷 없이 바로 바뀐다)

- **규칙은 한 곳이다** — `src/shared/viewTransitions.ts`의 `navTransitionType(출발, 도착, 형제 순서)`.
  깊이가 다르면 깊이가 정하고, 같으면 형제 순서(이전·다음)가 있을 때만 정한다. 깊이가 순서보다 먼저라
  시리즈 마지막 편의 "시리즈 목록 →"(오른쪽 자리)도 헤더 '시리즈'와 같은 `nav-back`이다 — 방향은
  링크가 아니라 이동의 성질이다. 깊이는 경로 세그먼트 수가 아니다(폴더 slug도 글 하나)
- **링크는 방향을 적지 않는다** — 사이트 안 링크는 `TransitionLink`(`src/components/shared/TransitionLink.tsx`)를
  쓰고, 그것이 현재 경로(`usePathname`)와 도착 경로로 type을 단다. 링크가 주는 것은 사실뿐이다: 형제
  순서(`order` — 이전·다음 카드만. "시리즈 목록 →"처럼 형제가 아닌 카드는 자리만 다음 쪽이고 순서를
  주지 않는다)와 글을 여는 카드인지(`opensPost`). `next/link`를 바로 쓰면 그 이동만 에러 없이 페이드로
  남으므로 lint가 막는다(`eslint.config.mts`의 `NEXT_LINK_DIRECT`). 허용은 `NEXT_LINK_FILES`뿐이다: 검색
  다이얼로그(결과는 모달을 닫으며 가는 이동 — 페이드), `ErrorFallback`(그것을 그리는 에러 경계에는
  페이지 전환 경계가 없다 — 아래), admin(공개 계층 밖의 도구 화면)
- **나감과 들어옴을 겹치지 않는다** — 나가는 쪽이 fast·exit로 걷힌 뒤 들어오는 쪽이 fast 지연·
  fastMax·standard로 들어온다. 투명도를 순서대로 두는 것은 가이드와 같지만(나가는 내용이 시선을 다투지
  않게), 가이드는 양쪽 슬라이드를 0ms부터 함께 돌리고 여기서는 들어오는 쪽의 자리도 지연한다 —
  standard는 앞에 몰린 곡선이라 처음부터 돌리면 보일 때 이미 거리의 대부분을 와 있어 방향이 안 보이고,
  같은 쪽으로 미끄러지는 두 페이지의 글자가 겹쳐 보인다. 공유 요소 제목과 같은 박자이고, 합(405ms)이
  공유 요소 그룹(medium)과 거의 같아 카드에서 열 때 커버·제목·본문이 함께 자리에 닿는다. 바뀌는 순간
  거의 빈 지면이 한두 프레임 보인다
- **카드에서 열 때도 방향을 단다** — 카드 열기만 페이드로 두면 새 글의 본문이 나가는 목록 위에 겹쳐
  보였다(실측 프레임 비교). 같은 이동(목록 → 글)이 카드로 열든 목록 행으로 열든 같은 방향이어야 하기도
  하다
- **거리 32px** — 들어오는 쪽이 지연 뒤에 출발해 거리 전부가 눈에 보인다. Next 가이드의 60px은 들어오는
  쪽이 처음부터 미끄러져 보이는 몫이 40px 안팎이고, Material shared axis는 30dp다. 방향 없는 페이드의
  8px 상승의 네 배라 방향이 읽히고, 375px 화면에서도 폭의 9%다. 값은 `panda.config.ts`의 `NAV_SLIDE_PX`
  한 곳이다
- **헤더는 미끄러지지도 페이드하지도 않는다** — 이름이 따로라 페이지 그룹 밖이고, 페이지 이동에서는 옛
  스냅샷을 숨기고 새 스냅샷을 그대로 둔다. 두 스냅샷을 겹친 페이드는 중간 프레임에 글자가 묽어져 로고가
  깜빡였다. 그래서 내비 라벨의 현재 위치(색·굵기)는 바로 바뀌고, 표식 막대만 따로 미끄러진다.
  크로스페이드(fastMax·standard)는 `theme-change` type이 붙은 테마 전환에서만이다. 공유 요소와 헤더의
  쌓는 순서(`VT_STACK`)는 그대로다
- **라우트의 내용은 경계 안에** — 404(`not-found.tsx`)도 페이지처럼 `PageBoundary`에 담고, admin은
  영역 전체를 서버 레이아웃(`src/app/admin/layout.tsx`)의 경계 하나로도 감싼다(이 경계는 영역을 드나드는
  이동만 움직이고, admin 안의 대시보드 ↔ 분석 이동은 각 페이지의 경계가 움직인다). 경계 밖 내용은 첫 프레임에 사라지는데 방향 있는 이동은
  들어오는 페이지가 fast 뒤에 나타나서, 경계 없는 화면에서 떠나면 그 사이 헤더만 남은 빈 지면이
  보였다(404 → 헤더 '글', 175ms). `PageBoundary`는 서버 컴포넌트에서만 쓴다 — 클라이언트 파일이 쓰면 그
  코드와 `VIEW_TRANSITION` 그룹 객체가 클라이언트 그래프에 들어와 공개 페이지 첫 로드가 무거워진다. 그래서
  클라이언트 컴포넌트인 에러 경계(`error.tsx`·`global-error.tsx`)는 경계 없이 뒀다(실측 +314B gzip)
- **경계 밖에 남는 것** — 글 하단 이전·다음 카드는 경계(`PageBoundary`)를 하나 더 둬서 글과 함께 밀린다.
  경계 밖(푸터·고정 버튼)은 React가 루트 스냅샷을 투명하게 두는 이동(경계 밖에 바뀐 것이 없다고 볼
  때)에서 첫 프레임에 사라진다 — 방향과 상관없는 기존 동작이다
- 하드 로드·해시 이동·`/posts` 안의 필터(쿼리만 바꾸는 얕은 갱신이라 내비게이션이 아니다)·브라우저
  뒤로·앞으로 가기(공유 요소 절)에는 페이지 전환 자체가 없고, 테마 전환은 루트·헤더만 돈다(방향
  없음). 움직임 줄이기면 시간·지연이 0.01ms라 거리가 있어도 즉시 바뀐다

**공유 요소(글 카드 ↔ 글 상세)** — 목록의 썸네일이 상세로 그대로 이어지고 주변은 페이지 전환대로
움직인다(ssgoi hero와 같은 구성, 라이브러리 없이 React `<ViewTransition>`). 이름·클래스·transition
type은 `src/shared/viewTransitions.ts`, 감싸개는 `src/components/shared/PostSharedElement.tsx`의 둘이다.

- **짝** — 커버(카드의 커버 틀 ↔ `PostHero`의 썸네일 틀)와 제목(카드·목록
  행의 h3 ↔ `PostHeader`의 h1). 커버는 **가로형 글만**(OG 카드, 가로/세로 1.6 이상의 자기 썸네일) 겹쳐 모핑하고(아래), 정사각 같은 자기 썸네일 글은 차례로 바뀌며, 다이어그램 히어로·
  히어로 없는 글은 제목만 짝이다. 쓰는 곳은 홈 카드
  두 변형·썸네일 행·`/posts` 피처·그리드 카드·글 목록 행(`PostListRow` — `/posts` 목록 보기와 `/series`, 제목만).
  새 카드는 `PostCardShared`로 감싸고 제목 링크를 `<TransitionLink opensPost>`로 둔다(글을 여는 type과
  방향 `nav-forward`가 함께 붙는다)
- **짝이 되는 이동은 둘뿐이다** — 카드를 눌러 글을 열 때(링크의 transition type)와, 그 글의 상세에서
  링크(헤더 내비·워드마크·태그·시리즈 목록)로 목록에 돌아갈 때(상세가 마운트 동안 "열린 글"로 적는다).
  목록 → 목록 이동(홈 → `/posts`)에서는 같은 글의 카드끼리도 짝이 되지 않는다 — 되면 화면의 카드
  열네 개가 한꺼번에 날아다녔다(실측). 검색처럼 카드가 아닌 링크로 열면 짝 없이 페이지
  전환만 한다(검색은 페이드)
- **양쪽이 화면 안일 때만** — React가 뷰포트 밖 요소의 이름을 거둔다. 상세에서 `/posts`로 돌아갔는데
  그 글의 카드가 화면 밖이면 상세의 커버·제목은 나가는 페이지와 같은 fast·exit로 사라진다(`:only-child`
  규칙 — 따로 찍힌 스냅샷이라 페이지와 함께 옆으로 밀리지는 않는다).
  카드 쪽도 같다 — 홈 첫 화면에서 쇼케이스 제목이 화면 아래에 있으면(데스크톱 높이 800 안팎) 커버만
  짝이 되고 제목은 페이지와 같이 바뀐다
- **커버는 늘이지도 겹치지도 않는다** — 카드는 원본의 가운데를 잘라(16:9 cover) 보인다. 상세도 OG 카드
  글은 같은 16:9 cover라, 두 스냅샷을 그룹 상자에 같은 16:9로 맞추면 원본의 같은 부분을 같은 배율로 그린다.
  그러려면 두 스냅샷 모두 이미지가 가장자리까지 차 있어야 한다: 카드 틀의 hairline은 이미지 위에
  덮어 그린 선이고(`coverFrameRaw`의 `_before`), 상세 히어로도 같은 틀이다(`PostHero`, 16:9). 틀의 진짜
  보더가 이미지를 1px 안으로 밀었을 때는 둘이 최대 4px 어긋나 이미지 속 글자가 두 겹이었다
- **가로형이 아닌 자기 썸네일 글은 커버가 겹치지 않고 차례로 바뀐다** — 상세 히어로가 16:9 틀에 contain이라(정사각이
  cover면 위아래 44%가 잘린다) 카드의 cover 크롭과 같은 그림이 다른 배율로 그려진다. 겹치면 글자가 두 겹으로
  보였다(정사각 8편, 실측). 판정은 `page.tsx`와 카드의 `isWideThumbnail` 한 함수이고(가로/세로 ≥ 1.6이면 가로형, 비율은
  `collectPosts`가 글 폴더 png·jpg의 머리말에서 읽는다) `PostHero`·카드가 `rescaled`로 받는다. 짝(같은 이름)은 그대로 두고 카드·상세가 클래스 `post-rescaled`를 같이 단다 — 짝은 들어오는
  쪽의 클래스만 받기 때문이다. 짝으로 두는 이유는 쌓는 순서다: 이름이 없으면 커버가 페이지 스냅샷에 섞여 그
  위에 쌓이는 제목 그룹이 그림 위를 지났다(자기 썸네일 11편, 실측). 이름 붙이는 길은 `share`뿐이다 — 중첩된
  `<ViewTransition>`의 `enter`·`exit`는 바깥 페이지 경계의 enter·exit가 덮어 이름이 붙지 않았다(실측). 규칙은
  나가는 스냅샷이 먼저 걷히고(fast) 들어오는 스냅샷이 그 뒤에 나타난다(fast 지연, fastMax) — 바닥(불투명한
  상세 스냅샷)을 두지 않아 두 그림이 같은 프레임에 겹치지 않는다. 그룹은 OG 글과 같이 커버 z-index라 제목 위에
  쌓이고, 제목은 걷히는 커버 뒤로 비친다
- **커버의 겹치는 방식** — UA 크로스페이드(plus-lighter로 두 장을 함께 흐리게)는 쓰지 않는다: 상자를
  늘 채우는 상세 스냅샷이 불투명한 바닥이고, 카드 스냅샷(같은 그림에 라운드·hairline·hover 틴트만 더
  있다)만 위에서 걷히거나 나타난다. 카드 스냅샷은 카드 크기에서만 바닥과 모양이 같아서 카드 → 상세는
  처음에 빨리(fast) 걷히고, 상세 → 카드는 그룹이 카드 크기에 거의 닿은 뒤(fast 지연, fastMax)
  나타난다. 바닥은 그룹 상자와 비율이 다르면(16:9가 아닌 썸네일 행) 라운드도 잘려 나가므로 모서리를 다시 깎는다 —
  카드 쪽 끝은 `container`, 상세 쪽 끝은 `element`로 그룹과 같은 시간에 바뀐다(히어로 스냅샷에 `container`
  라운드가 이미 찍혀 있어 상세 쪽 끝은 화면에 드러나지 않는다). 짝의 그룹은 들어오는 쪽 요소의
  클래스만 받아서, 방향은 `post-card`/`post-detail` 클래스로 가른다. 상세 히어로는 카드와 같은
  주소(`resolveThumbnailSrc`)라 이미 받은 이미지다
- **제목은 순서대로 바꾼다** — 카드(14~24px, 좁은 칼럼)와 h1(22px, 752px)은 글자 크기도 줄바꿈도
  달라 스냅샷을 그룹 크기로 늘이면 글자가 뭉갠다. 제 크기 그대로 그룹 왼쪽 위에 붙여 자리만 옮기고,
  두 글자가 겹치지 않게 나가는 제목이 먼저 사라진 뒤(fast·standard — 처음에 대부분 걷힌다) 들어오는
  제목이 나타난다(fast 지연, fastMax). 그룹 상자 밖은 자른다 — 752px 한 줄 h1이 254px 카드 제목으로
  줄어드는 동안 글자 끝이 옆 카드 위를 지나갔다
- **쌓는 순서** — 내비 표식 > 헤더 > 커버 > 제목 > 페이지(`panda.config.ts`의 `VT_STACK`). 기본 순서면
  들어오는 페이지가 날아가는 커버 위에 덧칠되고, 헤더 밑에 반쯤 가린 채 눌린 카드는 가려진 부분까지 찍혀
  헤더를 덮는다. 제목이 커버 아래인 이유: 카드 제목은 커버 아래, 상세 h1은 히어로 위라 제목이 날아가는
  커버를 가로지르는데, 위에 그리면 다크에서 흰 글자가 커버 그림 위를 지나갔다. 내비 표식은 헤더 안에
  있지만 이름이 따로라 헤더 스냅샷에 없고, 헤더 그룹의 불투명 지면 아래에 있으면 가려진다
- **브라우저 뒤로·앞으로 가기는 지원하지 않는다(보류)** — Next 16.4 `handlePopState`는
  `traverse`를 `startTransition`으로 넘기지만, React DOM이 popstate 이벤트 안의 전환을 동기 레인과
  묶어 그 자리에서 커밋하고(브라우저 스크롤 복원이 새 페이지에 걸리게) 동기 레인이 섞인 커밋은 View
  Transition을 열지 않는다(실측 `startViewTransition` 0회, 스크롤은 1500px 그대로 복원). Next 가이드는
  "뒤로 가기에도 모핑은 남는다"고 적지만 이 조합에서는 재현되지 않는다. 프레임워크가 여는 길이 없어
  Navigation API 가로채기 같은 우회는 넣지 않았다 — 스크롤 복원과 싸운다
- 하드 로드·같은 페이지 해시 이동·테마 전환에는 끼지 않는다(실측). 움직임 줄이기면 시간 토큰이
  전부 0.01ms라 즉시 바뀐다

**Astryx와 일부러 다르게 간 곳**

- **페이지 전환과 공유 요소는 블로그 것이다.** Astryx에는 페이지 전환이 없다. 링크 이동에서만 돌고,
  브라우저 뒤로·앞으로 가기에는 전환이 아예 없다(스크롤 복원만 일어난다 — 공유 요소 절) — 방향(앞·뒤로
  미끄러짐)도 링크 이동에서만 보인다. 시간·곡선은 Astryx 토큰 그대로이고(나감 fast·exit, 들어옴 fast
  지연·fastMax·standard), 방향 없는 페이드의 8px 상승은 Astryx spacing-2(Toast 등장 거리)다. 방향의 32px는
  Astryx에 대응하는 값이 없어 Next 가이드와 Material shared axis에서 정했다(방향 절)
- **스켈레톤의 쉬는 투명도가 다르다.** Astryx는 .25↔1이지만 자리표시 면(`paper.200` — admin 바닥·카드
  어느 쪽에서도 한 단계 진하다)이 지면과 가까운 밝기라 .25에서는 보이지 않는다 — 1↔.5로 왕복한다. 곡선도 Astryx의 `steps(10, end)`가 아니라
  `linear`(스켈레톤 하나를 위해 곡선 토큰을 늘리지 않는다)이고, 1초 지연은 두지 않았다
- **맨 위로 FAB 등장은 fast다.** Astryx 레이어(팝오버) 등장은 fastMax지만 FAB은 레이어가 아니라
  토스트처럼 나타나는 버튼이라 토스트(fast)를 따른다
- **목차 FAB에는 등장이 없다.** Astryx FAB 예제와 달리 — 하이드레이션 뒤 모든 글에서 삽입된다
  (`@starting-style` 규칙)
- **엇갈린 진입(`stagger`)은 블로그 것이다.** Astryx 모션 스케일에는 간격 단계가 없다
- **누름은 블로그 것이다.** 시간·곡선(press 40ms 감속 · release 320ms easeInOutQuad · 크기만 spring
  520ms)과 투명도(링크 0.3 · 버튼·토글 0.5)는 Astryx가 아니라 iOS 하이라이트에서 정했다 — 닿는 순간 켜지고
  떼면 천천히 꺼져 짧은 클릭에도 잔상이 남는다(WWDC18 803 "the button should highlight immediately when I
  touch down on it"). Astryx의 누름(98%·fast)은 100ms 클릭에 목표 깊이의 97%까지 가지만 32px 버튼의 한 변이
  0.3px만 움직이고 125ms 안에 돌아와 보이지 않았다(2026-10 실측). Apple은 하이라이트의 알파·시간을 공개하지
  않아 투명도는 근사다 — WebKit 탭 하이라이트 알파 0.4, React Native `TouchableOpacity` 0.2·놓음 250ms, Flutter
  `CupertinoButton` 0.4 사이에서 골랐다. 스프링 감쇠 0.5는 WWDC 권장(100%·운동량이 있으면 80%)보다 낮다 —
  놓음에는 제스처 운동량이 없어, 100%면 오버슈트가 없고 80%여도 1.5%(97%에서 놓으면 0.05%p)라 보이지 않는다
- **admin 지표에 카운트업이 없다.** CSS(`@property` 정수 + `counter()`)는 정수만 찍어 `7.8K`·`7,805` 표기를
  낼 수 없고, 의사 요소의 글자는 접근 이름이 아니라 실제 숫자를 한 벌 더 둬야 한다 — JS 루프 대신 값 줄
  교체(`out`·`rise`)로 갈음했다
- **admin 정렬은 행을 옮기지 않고 목록을 교차한다.** 행마다 경계를 두고 새 자리로 미끄러뜨려 보니 표의 칸
  선(border-collapse)은 표가 그려 행 스냅샷에 실리지 않아 선은 제자리에 남고 글자만 움직였고, 정렬을 뒤집으면
  46행이 화면 밖까지 서로를 가로질렀다

## 인터랙션 상태 — hover · 누름 · 초점 · 비활성

상태의 **때**는 `panda.config.ts`의 `conditions`가, 누르는 **모양**의 공통부는 `src/components/interaction.ts`의
프리셋이 정한다. 컴포넌트는 `_hover`에 면·색·밑줄 **값만** 적는다 — 터치에서는 그 값이 누르는 동안 켜지므로,
마우스의 hover와 터치의 누름 면을 한 줄이 함께 맡는다. 누름의 투명도·크기는 프리셋이 더한다. 조건은 Panda 기본
`_hover`·`_groupHover`를 **덮어쓴다**(이름이 같아 컴포넌트 diff 없이 전부 따라온다):

| 조건                     | 뜻                                                                                                                                                                           |
| :----------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `_hover` · `_groupHover` | `@media (hover: hover)`에서는 올린 동안, `(hover: none)`(터치)에서는 누르는 동안(`:active`). 터치의 탭 뒤 `:hover`가 남는 고착은 이 조건이 막는다                            |
| `_press` · `_groupPress` | 모든 포인터에서 누르는 동안 — 누름의 투명도·크기·덮개와 진입 전환, hover와 **다른** 모양(카드 커버 hairline·밝기, 검색 결과 행). `_press`는 `:disabled`·`aria-disabled` 제외 |
| `_groupKeyboardFocus`    | 그룹 자신이나 안쪽에 **키보드 초점**(`:focus-visible`)이 있는 동안 — 카드의 제목 링크가 초점을 들면 커버 틴트가 켜진다. `:focus-within`이 아니다                             |
| `:focus-visible`         | globalCss `FOCUS_RING` 하나(2px `accent.solid`, offset 3, `inner`)                                                                                                           |

**누름의 시간** — 누르면 바로 바뀌고 놓으면 천천히 돌아온다. 투명도·크기·커버 밝기는 누를 때 `press`(40ms
감속), 놓을 때 `release`(320ms easeInOutQuad)이고, 크기의 놓음만 `spring`(520ms — 202ms에 버튼은 94%에서
101%까지, 카드는 97%에서 100.5%까지 갔다 가라앉는다)이다. 카드만 들어가는 움직임(크기·커버 밝기)이 hover
박자(fast·standard)다 — 큰 면이 40ms에 움직이면 뚝 떨어져 보였다(아래 크기 항목). 색은 hover와 같은 fast·standard다. CSS는 도착 상태의 `transition`을 쓰므로 누름
조건의 규칙이 press를, 평상시 규칙이 release를 든다(`pressTransition` — 모션 절 "쓰는 법"). 놓은 뒤 80ms에도
거리의 13%만 돌아와 100ms 클릭에도 눌린 모양이 클릭 뒤까지 보인다.

누름은 마우스와 터치가 같다(터치의 면은 `_hover`가 누르는 동안 켠다).

| 종류                                                        | hover                                     | 누름                                                                  | 쓰는 것                                                                               |
| :---------------------------------------------------------- | :---------------------------------------- | :-------------------------------------------------------------------- | :------------------------------------------------------------------------------------ |
| 버튼(행동·아이콘)                                           | 면 한 단계                                | hover 면 + 투명도 0.5 + 94%                                           | `pressButton`(`actionButton`·`iconButton`)                                            |

| 켜고 끄는 칩                                                | 면 한 단계                                | hover 면 + 투명도 0.5 + 96%                                           | `pressToggleChip`(`chip` toggle)                                                      |

- **투명도는 종류로 가른다.** 링크(글자·목록 행·헤더 내비·워드마크)는 0.3, 버튼·토글은 0.5다 — 글자는 면이
  없어 글자가 신호의 전부라 사라지지 않는 선에서 깊게, 면은 옅어지면 지면색에 가까워져 얕게 잡았다. hover 면이
  있는 헤더 내비도 링크라 0.3이고, 면이 없는 글자 버튼(검색 지우기·admin 정렬 머리)도 버튼이라 0.5다. 카드는
  투명도를 바꾸지 않는다 — 커버가 어두워지는 것이 대신한다
- **크기는 버튼 94%, 상자 링크(헤더 내비·워드마크)·켜고 끄는 칩 96%, 카드 97%(md 이상 98%)이고 터치에도
  준다.** 놓으면 크기만 spring으로 살짝 튀었다 돌아온다. 보기 토글 칸·탭은 칸 뒤에서 미끄러지는 표식 면과 어긋나
  투명도만 준다(칸의 글자만 옅어지고 표식 면은 그대로다). 인라인 링크는 transform이 걸리지 않는다(비대체 인라인
  요소). 카드가 버튼보다 얕고 느린 건 상자가 커서 같은 비율이 먼 거리라서다 — 40ms에 97%면 PC 글 목록의 752px
  카드가 한쪽 11px을 두 프레임에 움직여 뚝 떨어져 보였다(사용자 지적, 실측). 그래서 카드는 hover 박자로 들어가고
  폭이 넓어지는 md부터 98%다(752px 카드 한쪽 7.5px, 깊이의 90%까지 85ms — 폰의 350px 카드는 97%로 5px). 터치에 크기를 주는 것은 2026-10-31 사용자
  결정이다 — 예전엔 터치의 `:active`가 스크롤을 시작하는 손가락에도 칠해진다는 이유(Astryx와 같은 판단)로 크기를
  마우스류에만 줬다(아래 "실기기 확인")
- **줄어든 가장자리는 덮개가 덮는다.** 요소가 줄면 가장자리가 포인터·손가락 밑에서 빠지고, 거기서 떼면 click이
  그 요소가 아니라 공통 조상으로 가서 아무 일도 일어나지 않는다. 누르는 동안 덮개를 크기만큼 넓힌다 — 버튼
  사방 3.5%+1px(94%에 필요한 3.19%에 여유, `inset`의 %가 보더 안쪽 기준이라 1px 보더만큼 더), 상자 링크 2.5%,
  카드 2%(`interaction.ts`의 `BLEED_INSET`). 버튼·상자 링크·카드 자신이 링크인 카드는 자기 `::before`, 글 카드는
  제목 링크의 덮개(`::after`)다. 켜고 끄는 칩에는 덮개가 없다 — 긴 이름을 말줄임하려는 면의 `overflow: hidden`이
  덮개를 자른다. 그래서 마우스로 칩의 양 끝 2%(82~255px 칩에서 1.6~5.1px)를 누르고 그대로 떼면 켜지지 않는다
- **커버 밝기는 이미지에만 건다.** 85%로 어두워지는 것은 틀이 아니라 `<img>`라 틴트·hairline은 그대로 위에
  남는다. `filter`는 이미지를 쌓임 맥락으로 만들어 위치 지정된 hairline 뒤에 그리므로, 틀을 `isolation`으로
  묶고 이미지를 그 안 맨 아래(`zIndex: -1`)에 둔다 — 틀의 면 위, hairline·틴트 아래라 순서가 그대로다.
  투명도와 달리 라이트·다크에서 같은 방향(어둡게)이다
- **카드의 눌린 크기는 글 상세 전환을 해치지 않는다** — 공유 요소 그룹은 조상의 transform을 그룹 transform으로
  받아 그 순간의 모양에서 이어 모핑하고, 전환 스냅샷의 `old` 크기는 그대로 레이아웃 크기다(실측). 이동을 여는 클릭은
  전환이 시작될 때까지 돌아온 만큼의 모양이 옛 화면 스냅샷에 찍힌다(dev 서버에서 놓은 뒤 100~260ms에 시작했다) —
  스냅샷은 정지 화면이라 옛 화면에서는 놓음이 더 진행되지 않는다. 헤더 내비·워드마크처럼 새 화면에도 남는 요소는
  새 화면에서 놓음이 이어 돈다. 페이지 전환 규칙은 누름 때문에 바꾸지 않았다
- **이름 붙은 요소를 안은 링크는 자식을 흐린다.** View Transition은 이름 붙은 요소의 스냅샷에 자기 투명도는 담고
  조상의 투명도는 버린다. 목록 행(제목 h3가 글 상세 h1로 이어지는 공유 요소)을 링크째 흐리면 글을 여는 전환의 첫
  프레임에 제목만 1로 튀었다(실측) — 그래서 행은 링크의 자식(제목·날짜)이 흐려진다(`pressTextShared`). 헤더 내비의
  표식 막대(이름이 따로다)는 같은 이유로 흐린 라벨 아래에서 진한 채 미끄러진다 — 175ms짜리라 그대로 둔다
- **떠 있는 버튼(맨 위로·목차 열기)은 옛 누름(98%·fast, 투명도 변화 없음 — `pressFab`)을 지킨다.** 둘 다
  누른 뒤의 모양이 버튼의 쉬는 모양에 묶여 있다. 맨 위로는 등장(`@starting-style`)도 누름과 같은 `transition`을
  타서 놓음(release)을 주면 등장도 320ms의 느린 출발로 바뀌고, 목차 열기는 바텀시트가 쉬는 버튼의 사본(투명도
  1·100%)에서 펼쳐져 옅은 버튼 위에 진한 사본이 튀어 오른다 — 펼침 자체가 누름의 피드백이다
- 누름의 면은 hover 면과 같은 값이다 — paper는 50·100·200·300 네 단이라 neutral·solid는 그 위가 없다. 그래서
  tone마다 누름 값을 따로 두지 않는다
- 그림자 · 글로우 · 그라데이션 · 떠오르기(translateY) 없음. 움직임 줄이기는 시간 토큰이 처리한다 — press·release·
  spring도 0.01ms라 투명도·크기가 잔상 없이 바로 바뀐다
- 비활성: `pressButton`이 투명도 .5 · `cursor: not-allowed`를 주고 `_press`가 누름을 뺀다. 값은 누름
  투명도(0.5)와 같지만 뜻이 다르다(누를 수 없음) — 비활성은 누름을 받지 않아 둘이 겹치지 않는다. 비활성으로 바뀌는
  투명도도 release(320ms)를 탄다. hover 면은 비활성에도 남는다 — 공개 화면에는 비활성 버튼이 없어 아직 맞출 일이
  없다. 비활성은 한 값이다: admin 로그인 버튼은 프리셋 그대로이고, 새로고침 버튼은 받는 중이라는 뜻으로 커서만
  `wait`로 바꾼다(투명도는 같다)
- **`transform`을 이미 쓰는 요소는 위치를 `translate`로 옮긴다.** 인라인 `transform`(QuoteLink의 화면 안
  가운데 맞춤)은 클래스의 `scale(0.94)`를 덮어 누름 크기가 조용히 꺼진다. 개별 속성 `translate`는 `transform`과
  겹쳐 적용되고 누름 프리셋의 전환 목록에 없어서, 위치가 스크롤·폭 보간을 따라 바뀌어도 미끄러지지 않는다
- 탭 하이라이트는 Panda preflight가 투명으로 지운다(`-webkit-tap-highlight-color`) — 터치 피드백은 `_hover`의
  면과 누름 프리셋의 투명도·크기가 맡는다
- **hover 갈래는 주 입력(`hover`)으로 가른다 — 의도한 절충이다.** 주 입력이 터치로 보고되는 기기(iPad +
  트랙패드·마우스)에서는 포인터를 올려도 hover가 켜지지 않고 누르는 동안만 켜진다. `any-hover: hover`로 넓히면
  그 기기의 손가락 탭에 hover 고착이 돌아온다 — 더 흔한 손가락 입력 쪽을 택했다
- **실기기 확인:** 터치에서 스크롤을 시작하는 손가락에도 `:active`가 잠깐 칠해지면 그동안 hover 면(카드 커버 틴트
  포함)과 누름의 투명도·크기·커버 밝기가 켜져, 스크롤하는 목록의 카드·버튼이 움찔거릴 수 있다. 그래도 터치에 다 준
  것은 2026-10 사용자 결정이다(투명도는 10-31 앞서, 크기·밝기는 10-31 모바일로 본 뒤) — 누름 피드백이 곧 그것이라서다.
  투명도·크기는 40ms(카드의 크기·커버 밝기는 175ms)에 켜지고 320ms(크기는 spring 520ms)에 걸쳐 돌아와
  면(175ms)보다 오래 남는다.
  - **Android Chrome — 확인했다(2026-10-31, 사용자 폰).** 누름이 보이고, 목록을 스크롤해도 움찔거리지 않았다.
    Chrome의 터치 에뮬레이션에서도 스크롤 드래그에는 `:active`가 켜지지 않았고, 탭에는 손가락을 뗀 뒤 13~16ms에
    133ms쯤 켜졌다. 확인한 판은 카드도 40ms에 들어갔다 — 지금의 175ms는 짧게 칠해지는 `:active`가 덜 드러나는
    쪽이다
  - **iOS Safari — 확인 전이다.** WebKit은 `:active`를 켜는 방식이 다르다(터치 리스너가 있는 요소에서 켠다 —
    React의 루트 리스너가 그 조건을 채운다). 목록·본문 스크롤과 가로로 미는 코드 탭 줄을 확인하고, 움찔거림이
    보이면 여기에 적고 다시 정한다
- **초점 링은 컴포넌트가 다시 정하지 않는다.** `outline: none`·`_focus`·`_focusVisible`로 지우거나 바꾸지 않는다
  (utilities 레이어가 base 레이어의 `:focus-visible`을 이겨 링이 사라진다). 입력은 감싸는 상자의 `_focusWithin`
  보더를 함께 둘 수 있다(`ArchiveSearchBox`). 카드는 링이 제목 상자만 두르고, 키보드 초점이 오면 커버 틴트가 hover 때와
  같이 켜져(`_groupKeyboardFocus`) 어느 카드인지 면으로도 보인다 — 마우스·터치로 누른 링크는 `:focus-visible`이
  아니라 켜지지 않는다. 링을 카드 전체로 옮기려면 `FOCUS_RING`을 `panda.config.ts` 밖의 값 모듈로 빼야 한다
- 누름·초점 조건과 누름의 전환(`pressTransition`)은 허용 파일 밖에서 쓰면 lint가 막는다 — 막는 이름과 허용
  파일은 `apps/blog/web/eslint.config.mts`의 `NO_LOCAL_INTERACTION`·`INTERACTION_FILES`가 단일 출처다. `:hover`를
  선택자 문자열로 적는 키도 막는데, Panda 조건을 거치지 않아 터치에서 탭 뒤에도 hover가 남기 때문이다.
  버튼 레시피 파일도 허용 파일이 아니라 프리셋(`pressButton`·`pressToggleChip`)을 펼친다.
  새 종류의 누름이 필요하면 `interaction.ts`에 프리셋으로 더한다

  (`css(chip.raw(…), {…})`)
- 강조 칩은 누를 수 없는 표식이라 hover가 없다
- **켜고 끄는 칩(`toggle`)은 네이티브 radio다.** 구조는 `span > input.peer(숨김) + label[for](칩 면) >
span(글자)`이고, 켜짐·hover·초점 링은 면이 **형제 선택자**로 받는다(`_peerChecked`, hover는
  `.peer:not(:checked) ~ &`로 켜진 칩을 뺀다 — 바깥 `span`이 형제 범위를 한 쌍으로 묶는다). `:has()`는
  쓰지 않는다 — Next 기본 대상의 Firefox 111~120에 없어 초점 링까지 사라진다. 초점 링은 globalCss가 같은
  형제 선택자로 `FOCUS_RING`을 준다. 켜질 때 semibold가 되어도 폭이 밀리지 않게 면은 글자를
  `data-label`로도 들고, `steadyLabel`(`src/components/steadyLabel.ts`)의 `::after`가 그 글자를
  semibold로 높이 0·`visibility: hidden`에 그려 폭만 미리 잡는다(면은 flex 세로 방향이라 글자와 사본이
  위아래로 쌓인다 — JS 없음, 접근성 트리에 없음). 강제 색상 모드는 면을 지우므로 켜진 칩에 밑줄을 더한다.
  줄 폭보다 긴 이름은 칩 안에서 끝을 말줄임으로 자르고 전체 이름은 면의 `title`에 남긴다. 말줄임은 면이
  아니라 글자 `span`에 건다 — `text-overflow`는 블록 컨테이너에만 걸려 flex 면 바로 밑 글자(익명 항목)에
  닿지 않는다. 면이 radio를 감싸는 `label`이 아니라 `label[for]` 자신인 이유는 글자 깊이다 — 감싸면
  글자가 label에서 세 단계 아래라 jsx-a11y `label-has-associated-control`(깊이 2)이 보지 못한다. 글 목록
  뷰 토글 칸은 글자가 잘리지 않아 `label > input.peer + span(칸)`이다(트랙 `paper.100`, 13px).
  다만 켜진 `paper.50` 면은 칸마다 칠하지 않고 면 하나가 고른 칸으로 미끄러진다 — 칸은 같은 폭
  (`gridAutoColumns: 1fr`), 면은 첫 칸의 grid 영역에 절대 위치로 겹치고 transform으로 옮긴다
  (fast·standard). 거리는 `translateX(calc(var(--segment-index) * (100% + 칸 사이)))`이고
  `--segment-index`는 React가 트랙에 내보내는 style 변수라 서버 HTML에도 있다. 면은
  `aria-hidden`·`pointer-events: none`이고 칸 글자는 `pos: relative`로 면 위에 그린다

## 카드 — 글 카드 · 썸네일 행

Astryx BlogCard·BlogFeatureCard·BlogShowcase의 블로그 판. `src/components/blog/`의 `PostCard`(종류
`showcase` · `default` — 홈, `feature` · `grid` — 글 목록), `PostThumbRow`, 메타 줄 `PostMeta`, 공통 조각
`cardParts.ts`. `PostCard`는 종류마다 배치(sva 변형)와 메타 줄의 태그 표시를 한 표(`CARD_KIND`)에서
정한다 — 태그 정책을 쓰는 쪽 prop으로 흩지 않는다.

| 부품     | showcase(홈)                                 | feature(글 목록)                  | default(홈)       | grid(글 목록)              | 썸네일 행                         |
| :------- | :------------------------------------------- | :-------------------------------- | :---------------- | :------------------------- | :-------------------------------- |
| 커버     | 16:9, `container`                            | 16:9, `container`                 | 16:9, `container` | 16:9, `container`          | 160×90(md 미만 128×72), `element` |
| 제목(h3) | `h3` → md부터 `h1`, 자르지 않음              | showcase와 같다                   | `h3`, 두 줄       | `h3`, 두 줄                | `h3`, 두 줄                       |
| 발췌     | `body` → md부터 `bodyLarge`, 두 줄           | `body` → md부터 `bodyLarge`, 전부 | `body`, 두 줄     | `body`, 두 줄              | 없음                              |
| 메타     | 날짜 \| N분 \| 앞 태그 셋(가운뎃점으로 이음) | 날짜 \| N분 + 앞 태그 둘 배지     | 날짜 \| N분       | 날짜 \| N분 + 첫 태그 배지 | 날짜 \| N분                       |
| 간격     | 커버·글·메타 사이 16, 제목·발췌 4            | showcase와 같다                   | 12, 제목·발췌 4   | default와 같다             | 썸네일·글 16, 제목·메타 4         |

- **피처 발췌는 자르지 않는다**(승인 목업은 세 줄) — 길이는 원고 excerpt 상한(check-seo
  `excerpt-length` 160자)이 막는다. 그리드는 홈 작은 카드와 같은 배치에 배지만 더한 것이다

- **카드 하나가 링크 하나(제목)다.** 목업은 커버와 제목에 링크를 따로 걸었지만, 그러면 탭 정지점과
  스크린리더가 읽는 같은 곳 링크가 둘이 된다. 제목 링크의 `::after`가 카드 뿌리(`position: relative`)를
  덮어 어디를 눌러도 그 링크다. 커버 `<img>`는 `alt=""`(바로 옆 제목이 이름)
- **줄 수 제한은 제목 링크 자신에 건다.** 부모 h3에 걸면 h3의 `overflow: hidden`이 초점 링을 자른다.
  자르지 않는 쇼케이스 제목은 `display: block` — 둘을 한 요소에 같이 주면 display 원자 클래스가 겨룬다
- **커버는 16:9 고정, `object-fit: cover`.** 정사각 원고 썸네일은 위아래가 잘린다(카드는 크롭을
  받아들인다 — 상세 커버와 다르다). 쇼케이스도 옆 열 높이를 따라 늘리지 않는다: 이미지가 오기 전후로
  높이가 같고(CLS), 생성 OG 카드의 글자가 잘리지 않는다(1200×630 카드를 16:9로 자르면 좌우 40px씩이고
  카드의 좌우 안전 여백은 90px). src는 `resolveThumbnailSrc` — 원고 썸네일은 `/thumbs/*.webp`, 없으면 `/og/{slug}.png`
- 커버 틀은 `paper.100` 면에 hairline. hairline은 틀의 보더가 아니라 이미지 위에 덮어 그린 선이다
  (`_before`, 라운드는 틀을 따른다) — 이미지가 틀 끝까지 차야 글 상세로 이어지는 전환에서 두 스냅샷이
  겹친다(모션 절). hover는 커버 위 `accent.muted` 틴트(`group` hover) — 밑줄은 쓰지 않는다. 누르는 동안은 틴트에 커버
  hairline이 `ink.borderStrong`으로 진해지고, 카드 뿌리가 97%(md 이상 98%)로 줄고 커버 이미지가 밝기 85%로 어두워진다
  (놓으면 크기는 spring, 밝기는 release로 돌아온다). 터치도 같다. 그동안 제목 링크의 덮개가 사방 2% 넓어져
  줄어든 가장자리를 덮는다. 키보드 초점이 제목 링크에 오면 hover와 같은 틴트가 켜진다(위 "인터랙션 상태")
- **이미지 우선순위는 `priority` 하나다** — 첫 화면에서 가장 큰 이미지(LCP 후보)만 `eager` +
  `fetchPriority="high"`, 나머지는 `lazy`. 여러 장에 걸면 화면 밖 이미지까지 받아 LCP가 밀린다
- 메타 줄은 mono `supporting`, `ink.700`, 항목 사이 세로선(1px × 0.75em, `ink.borderStrong`,
  `aria-hidden`). 읽기 시간 표기는 `@blog/content`의 `fmtReadMin`(`N분`) 하나다. 태그 배지(`badges`)는
  읽기 시간 뒤에 **구분선 없이** 줄 간격(8)만으로 잇는다 — 면이 있어 이미 항목으로 갈린다(승인 목업)
- 카드 안의 태그는 링크가 아니다(카드 링크 안에 링크를 둘 수 없다) — 태그 필터로 들어오는 입구는
  글 상세의 태그다
- **커버 틀과 제목 h3는 글 상세로 이어지는 공유 요소다**(모션 절) — 커버는 `<img>`가 아니라 틀
  (라운드·hairline)째 `PostCardShared`로 감싼다. 이름이 붙은 요소는 조상의 자르기 없이 따로 찍혀,
  이미지에 이름을 달면 틀의 라운드가 빠져 전환 첫 프레임에 모서리가 각진다. 제목 링크는
  `<TransitionLink opensPost>`다(글을 여는 type과 방향)

- **자기 썸네일** = frontmatter `thumbnail`이 있고 생성 OG 카드(`/og/…`)가 아니다(`hasAuthoredThumbnail`).
  커버는 이 판정이 아니라 **가로형인가**(`isWideThumbnail` — OG 카드는 언제나 가로형, 자기 썸네일은 가로/세로 ≥ 1.6,
  `WIDE_THUMBNAIL_MIN_ASPECT`)로 갈린다. 비율은 `collectPosts`가 글 폴더 png·jpg의 파일 머리말에서 읽어 `thumbnailAspect`로
  붙이고, 모르면(외부 URL·없는 파일) 가로형이 아니다. 가로형은 **cover**이고 카드 커버와 **모핑**한다(OG 카드와 1200×630
  자기 썸네일 3편 — 1.9:1이라 16:9에 거의 차고, 카드도 같은 cover라 같은 배율). 제목이 박힌 그림이 h1 아래에 한 번 더
  나오지만 모핑을 위해 받아들였다(사용자 결정 — "16:9 썸네일은 모핑 유지"). 정사각 등은 16:9 틀에 **contain**(자기
  썸네일 11편 중 8편이 정사각이라 cover면 위아래 44%가 잘린다)이고 카드 커버와 **겹쳐 모핑하지 않는다**(차례로 바뀐다)
- 이전·다음 카드는 글 칼럼 안이라 페이지 전환 경계 안이다 — 경계 밖이면 누른 카드가 전환 첫 프레임에 사라졌다
- 랜드마크 이름은 `주요 메뉴` · `위치` · `이 글의 차례` · `이전·다음 글` · `사이트 링크`로 서로 다르다
- 목차 시트(모바일)는 `MobileTOC` — 버튼 자리에서 `clip-path`로 펼쳐지고, 항목을 누르면 전환 없이 닫혀
  스크롤과 겹치지 않는다. 버튼 상자(`FAB` 상수)와 시작 모양이 한 곳에서 나온다

## 코드 블록

표면이 **테마를 탄다.** 예전에는 "코드는 라이트에서도 항상 어둡다"가 규칙이었다.
구문 강조 테마(`vscDarkPlus`)의 색이 다크 배경 전용 고정값이라, 배경만 밝히면
대비가 통째로 무너졌기 때문이다. 지금은 그 색들을 `code.*` semanticToken으로 옮겨
라이트/다크 두 벌로 쓴다(`src/components/post/codeTheme.ts`). 레퍼런스(fumadocs)가
shiki 듀얼 테마로 푸는 문제를, 색 **정의**를 토큰으로 옮겨 같은 원리로 푼 것이다 —
색이 마크업이 아니라 스타일시트에 한 번만 있으므로 HTML은 오히려 가벼워진다.
라이트는 github-light 계열이고, 다크 구문 색은 `vscDarkPlus` 그대로다. 다크 **표면**은 예전 `#0b0d10`이 지면
(`paper.50`)과 같은 색이라 상자가 보더만 남았다 — 목업의 `#14171c`로 올렸고(`code.surface`), 탭 바
`code.chrome`은 `#1b1f26`, 다크 주석은 대비 4.8 이상인 `#7ca668`이다(`codeTheme.test.ts`가 두 테마의 모든
구문 색이 표면 위 AA를 넘는지, 주석이 표면·탭 바 위에서 4.8 이상인지 잠근다).

- 색을 고칠 일이 생기면 `blog-preset.ts`의 `code.*` **한 곳만** 본다. 컴포넌트에
  hex를 다시 박지 말 것 — `codeTheme.test.ts`가 "원본 테마의 색이 하나도 남지
  않았다"를 검사하므로, 매핑에서 빠진 색은 테스트가 잡는다
- 매핑은 **색 기준**이라 원본에서 같은 색이던 토큰은 라이트에서도 같이 움직인다.
  셀렉터로 따로 가른 예외는 셋뿐 — `tag`(키워드와 `#569cd6` 공유 → `code.tag`),
  `inserted`·`deleted`(각각 숫자·문자열과 색을 공유해 라이트 diff에서 +/−가 둘 다
  파랑이 됐다 → `code.inserted`·`code.deleted`). 예외를 늘릴 땐 "라이트에서
  갈라지는 게 읽기에 실제로 도움이 되나"를 기준으로 (`codeTheme.ts` 주석)
- 펜스 메타(` ```ts title="lib/foo.ts" `, `tab="npm"`)는 `rehypeCodeMeta`가
  `data-*` 속성으로 승격한다. 이 플러그인은 **`rehypeRaw`보다 앞**이어야 한다
  (rehypeRaw가 트리를 직렬화·재파싱하며 hast의 `data`를 버린다). 순서가 뒤집혀도
  에러 없이 파일명만 조용히 사라지므로 `codeMeta.test.tsx`가 그 대조군까지 고정해 뒀다
- 헤더는 **항상** 그린다(탭 안의 블록 제외). 표면과 같은 면이라 보더로 가르지 않고, 라벨(mono 12/20 500
  `ink.700`)과 복사 버튼(`iconButton` sm)만 둔다. 라벨은 파일명 → 언어 → `text` 순서로 하나다.
  `<code-tabs>`로 묶으면 상단 바(`code.chrome`)를 탭이 가져가고, 복사 버튼은 열려 있는 탭의 코드를 집는다
- 코드는 14/20 mono로 **줄바꿈**한다(`pre-wrap`). 600px을 넘는 코드는 블록 안에서 세로로 스크롤되고,
  그 스크롤 컨테이너(`pre`)가 키보드 초점을 받도록 `tabIndex={0}`을 둔다(axe `scrollable-region-focusable`).
  `codeTagProps.style`은 테마의 `code` 규칙을 **합치지 않고 대체**하므로 테마 규칙을 펼친 위에 덮는다 —
  빠뜨리면 글꼴이 UA 기본 monospace로 떨어진다(런타임 게이트 `웹 폰트`가 잡는다)
- 인라인 코드는 `paper.100` 면에 14px mono, `inner` 라운드, 글자색은 둘러싼 글을 따른다. `paper.100` 면 위
  (`<msg>` 버블·`<metric>` 카드)에서는 칩이 면과 같아져 사라진다 — 그 안에 인라인 코드를 넣을 일이 생기면
  그 컨테이너에서 `code`의 `bg`를 한 단계 올릴 것. 본문 `<details>`는 같은 이유로 면을 깔지 않고(보더만)
  인라인 코드 칩과 코드 블록이 그 위에서 보이게 한다
- 복사 버튼의 아이콘 교차(복사 → 체크)와 인용 링크 알약의 아이콘은 `MorphSwap`이다: 두 면이 늘 DOM에 있고
  루트의 `data-on` 하나로 opacity와 scale(.75 ↔ 1)이 fast·standard로 양방향을 돈다(blur는 합성되지 않아
  쓰지 않는다). 알약 폭은 JS 없이 라벨마다 둔 grid `0fr ↔ 1fr` 칸의 합으로 보간한다(`QuoteLink.tsx` 주석)
