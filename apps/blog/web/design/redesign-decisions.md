# 블로그 리뉴얼 — 결정 기록

이 문서는 **왜 그렇게 정했는지**만 답한다. 리뉴얼(2026-07~08)에서 무엇을 고르고 무엇을
버렸는지, 그리고 만들면서 그 결정이 어디서 바뀌었는지의 기록이다.

**지금 유효한 규칙과 수치는 여기 없다.** 이 문서의 값을 근거로 코드를 고치지 말 것 —
반대 방향이 맞다. 현행 단일 출처는 다음과 같다:

| 무엇                      | 어디                                         |
| :------------------------ | :------------------------------------------- |
| 색·크기·라운드 등 토큰    | `packages/@blog/preset/src/blog-preset.ts`   |
| 디자인 시스템 수치와 근거 | `.claude/skills/blog-design-system/SKILL.md` |
| 디자인 금지선             | `AGENTS.md` 의 "Blog — design guardrails" 절 |
| 마크다운 커스텀 태그      | `.claude/skills/blog-components/SKILL.md`    |
| 다이어그램 저작법         | `.claude/skills/blog-diagrams/SKILL.md`      |

출처는 claude.ai 디자인 세션의 착수 초안이다. 초안을 그대로 두면 읽는 사람이 폐기된
수치를 먼저 읽게 되므로, **결정과 정착 결과를 한 문단에 합쳐** 다시 적었다.

## 1. 어떤 블로그를 만들려던 것인가

blog.sangwook.dev — 개인 프론트엔드 블로그다. 글은 디자인 시스템, 모노레포/Turborepo,
CI/CD·인프라(ECS, Docker), TypeScript 설계, 오픈소스 기여기가 대부분이고, 형태에 공통점이
있다: 대화체 도입부, 문제→시도→실패→해결의 전개, 수치로 끝맺는 결론(408ms→107ms 같은),
구조 그림 다용, 시리즈 연재. 리뉴얼은 **이 형태를 화면이 받아주게** 만드는 일이었다.
시그니처 컴포넌트 셋(§7)이 여기서 나왔다.

velog(@rewq5991) 크로스포스팅은 당시 하고 있었으나 **접었다.** 히어로의 velog pill과
GA 추적 코드를 함께 걷어냈다.

## 2. 확정한 컨셉

두 갈래의 하이브리드로 갔다.

2. **다이어그램 아이덴티티** (레퍼런스: blog.maximeheckel.com) — 구조 그림이 썸네일이자

그 밖의 레퍼런스: ishadeed.com(인라인 데모).

## 3. 타이포그래피

본문·UI는 Pretendard(variable), 날짜·수치·태그·코드는 JetBrains Mono. 갈라놓은 이유는
"측정하는 엔지니어" 무드가 이 블로그 글의 성격이라서다 — 숫자가 sans로 나오면 그 무드가
사라진다.

다만 **숫자가 있다고 기계적으로 mono를 쓰지는 않는다.** 시리즈 배지
(`시리즈 · 번들러 만들기 2/5`)는 안에 숫자가 있어도 본문 성격의 라벨이라 sans로 뒀다.

**2026-10: 크기는 역할 이름(textStyles)으로 고른다.** 자리마다 `fontSize`와 `lineHeight`를 따로 적던
것을 Astryx 코어 타이포 스케일의 역할 이름(`display1`·`h1`·`body`·`label`·`supporting` …) 하나로 묶었다.
값은 승인 목업의 수치를 그대로 썼고, 한 PR(셸)에서 열셋을 한꺼번에 정의했다 — 홈·글 목록·글 상세 PR이
층마다 프리셋을 고치면 스택이 서로 부딪힌다. 쓰지 않는 역할은 CSS로 나가지 않아 무게가 없다. 자간은
두지 않았다(Astryx는 normal이고, 한글에 음수 자간을 주면 받침이 붙는다). mono·sans 구분(위)은 그대로다
— 목업의 날짜·태그가 sans인 건 Astryx 테마에 mono가 연결되지 않은 부작용이라 따르지 않았다.

## 4. 컬러 — 무채색, 포인트색은 잉크

처음엔 무채색 베이스에 포인트 한 색을 따로 골라 썼다(2026-10에 잉크로 옮기며 따로 고른 색은 없어졌다 —
아래). 무채색 값은 초안 그대로 정착했다.

**포인트색은 틸에서 cyan으로 바꿨다.** 두 가지 이유다 — 다크 모드에서는 더 밝은 톤이라야
읽히고, 틸은 success 그린과 색상각이 가까워 의미색과 헷갈렸다.

또 하나, 포인트색은 한 값이 아니라 **용도별 세 단계**로 갈렸다: 선·아이콘용, 링크·배지용
(글자 대비가 WCAG AA를 넘어야 한다), 제목용. 토큰으로는 여기에 틴트·보더·hover가 붙어
여섯 단계(`accent.50`~`accent.900`)였다.

쓰는 자리도 초안보다 넓었다. 초안은 "링크·시리즈 배지·다이어그램 핵심 경로"였는데 한때는
**제목 계열**(홈·About 이름, 대표글 제목, 글 제목, 본문 h1·h2)까지 포함했다. 대신 섹션
라벨·목록 제목·본문 h3·h4는 무채색으로 남겼다.

**2026-10: 포인트색을 본문 잉크로 옮겼다.** Astryx docsite 테마(MIT)를 들이며 그 테마의 구조 —
accent 토큰 전부가 그 테마의 primary 텍스트 잉크다 — 를 따랐다. 따로 고른 색이 없어지니 링크·현재
위치는 밑줄·굵기·틴트로 가른다. 위의 "포인트 한 색"·"용도별 세 단계"·"제목 계열에 색" 결정은 이때 폐기됐다 —
제목은 본문 잉크이고 크기로 갈린다. cyan은 OG 카드의 브랜드 색으로만 남았다(카드 디자인은 바꾸지
않았고, 그 카드가 썸네일인 글은 홈·목록에서 여전히 cyan이 보인다). 현재 값과 구분 수단은
`blog-preset.ts`의 `accent.*` 주석과 `blog-design-system` 스킬에 있다.

## 5. 라운드·보더 — 위계는 보더로만

카드 12px / 작은 요소 8px. **배지는 pill이 아니라 6px로 정착**했다.

**2026-10: 라운드 스케일을 Astryx docsite 테마(MIT)의 것으로 바꿨다.** 이름이 크기(`sm`·`md`)나
한 용도(`card`·`control`)가 아니라 자리(`inner`·`element`·`container`·`page`·`full`)라서, 새
요소는 이름만 보고 값을 고른다. 카드는 12px에서 16px로 커졌고 버튼·배지는 pill이 됐다 — 위의
"배지 6px" 정착은 이때 폐기됐다.

보더는 hairline 하나다. 초안은 "0.5~1px"이라는 범위였는데 폭이 갈리면 같은 화면에 두
굵기가 섞이므로 **1px 단일값**(`borderWidths.hairline`)으로 고정했다.

그림자 대신 보더로 위계를 표현하고 **그라데이션·글로우·장식 효과는 금지**다. 지면 위 요소에서는
이건 지금도 그대로 지켜진다.

**2026-10: 그림자를 떠 있는 표면에만 들였다.** 흐름 밖에 떠서 아래를 가리고 닫히면 사라지는
면(다이얼로그·바텀시트·차트 툴팁)은 Astryx 코어의 그림자 두 단계를 쓴다 — 지면 위 카드·버튼·hover는
여전히 보더뿐이다. 본문 raw HTML용 형광펜 클래스(하드스톱 그라데이션)는 쓰는 글이 없어 이때 지웠다.

## 6. 다이어그램

이미지가 아니라 **SVG React 컴포넌트**로 그린다. 다크모드 색 전환이 자동으로 따라오고,
좁은 화면에서 줄어들고, 글자가 검색되기 때문이다.

문법은 회색(구조) + 액센트(핵심 경로) **2색뿐**, 실선 = 동기 호출 / 점선 = 비동기·데이터
흐름, 부제는 5단어 이내, 노드는 라운드 사각형 `rx=8` 에 스트로크 1px.

**라벨 크기는 의도가 14px + 12px였는데 12px + 11px로 정착했다.** 640px 폭 안에 노드
서넛이 들어가야 해서다. 단일 출처는 `apps/blog/web/src/components/diagram/layout.ts` 의
`TITLE_FONT_SIZE` / `DESC_FONT_SIZE`.

강조 노드를 고르는 prop은 `tone="accent"` 다. 값이 뜻하는 건 색이 아니라 "핵심 경로"라서,
팔레트가 바뀌어도 안 흔들리는 이름으로 바꿨다. 초안 시절 색 이름 `tone="teal"`은 옛 글을 위한
별칭으로 남아 있다가, 원고 사용이 0건이라 2026-10에 지웠다.

저작법 전체(선언형 태그, 레지스트리, `hero:`)는 `.claude/skills/blog-diagrams/SKILL.md`.

## 7. 페이지와 시그니처 컴포넌트

### 홈

네비는 **글 · 시리즈 · About**이다. 초안에는 오픈소스와 발표가 독립 메뉴였는데, 둘 다
About 페이지 안의 섹션으로 들어갔다.

**히어로 우측의 장식 다이어그램은 뺐다.** `aria-hidden` 장식이라 정보가 0인데, 정작
다이어그램이 뜻을 갖는 자리(글 히어로·본문)와 언어가 겹쳐 그쪽 무게를 깎았다. 다이어그램은
글 안에서만 쓴다. 소셜 pill도 github / rss 둘뿐이다(velog 제외 — §1).

하단 오픈소스 스트립의 칩은 4개(node.js / next.js / gemini-cli / mantine)이고, merged 수는
빌드 타임에 주입된다(`NEXT_PUBLIC_PR_COUNT`, 폴백 58).

### 헤더·푸터(셸)

**2026-10: 셸을 Astryx docsite의 TopNav·SiteFooter 모양으로 바꿨다**(승인 목업). 결정과 이유:

- **헤더는 구분선 없이 반투명 지면과 흐림으로만 뜬다.** 아래 hairline이 하던 "지면 위에 떠 있다"는
  표시를 흐림이 대신한다. 슬롯은 워드마크 | 내비 | 아이콘 셋이고 내비가 화면 가운데에 선다.
- **헤더·푸터는 레일 없이 전폭이다.** 그 전에는 `railWide`에 있었다. 어느 페이지에서나 같은 자리라는
  성질은 화면 양끝에 붙여도 그대로이고, 목업의 좌우 여백(헤더 8+8, 푸터 24)은 거터 단일 출처를 따라
  거터로 바꿨다 — 워드마크 글자가 거터 선에서 시작한다.
- **홈에서는 내비의 현재 위치를 켜지 않는다.** 목업은 홈에서 "글"을 켰지만 그 링크는 `/posts/`를
  가리키고, 홈을 가리키는 내비 링크는 없다.
- **좁은 화면(md 미만)은 헤더를 한 줄로 지킨다.** 목업에 정의가 없어 정했다 — GitHub·RSS를 숨기고
  (푸터에 같은 아이콘이 있다) 아이콘과 내비 여백을 줄여 360px 기기에 들어가게 했다.
- **푸터의 GitHub·RSS는 아이콘으로만 둔다.** 목업은 같은 두 링크를 글자 링크와 아이콘으로 두 번
  그렸다. 헤더와 히어로의 겹침은 목업 의도라 남겼다.
- **검색 트리거는 아이콘 버튼이다.** "검색 ⌘K" 글자 버튼이 사라져 단축키는 툴팁(`title`)과
  `aria-keyshortcuts`로만 알린다.
- **버튼 레시피를 둘로 정리했다** — 글자 버튼(`actionButton`: solid·neutral·ghost × 32·36)과 아이콘
  버튼(`iconButton`). 주 버튼의 hairline 보더(와 그것만 쓰던 색 토큰)를 걷었다 — Astryx 버튼에는 보더가
  없다. 대신 투명 보더를 남겨 강제 색상 모드에서 버튼 경계가 그려지게 했다.
- **헤더 높이에 기대는 값은 전부 그 상수에서 계산한다.** 차례·글 목록 사이드바의 sticky 위치와 최대
  높이가 px로 박혀 있었고, 정책·admin 화면은 "푸터를 바닥에 붙이려고" 헤더·푸터 높이를 손으로 뺀 최소
  높이를 들고 있었다. 레이아웃이 이미 flex 열(`main` flex 1)이라 그 최소 높이들은 지웠다.

### 글 상세

시리즈 배지 + 제목 + 메타(날짜·읽기시간·태그, mono) → 히어로 다이어그램 → 본문. 초안
그대로 정착했다. 히어로는 frontmatter `hero:` 로 붙인다.

### 시그니처 컴포넌트 셋

`<dialogue>`(도입부 대화 재현) · `<metrics>`(before/after 수치) · `<timeline>`(시도1 실패 →
시도2 실패 → 시도3 성공). §1에 적은 글의 형태를 그대로 받는 세 개다.

**MDX 컴포넌트가 아니라 소문자 raw HTML 커스텀 태그다.** MDX를 도입하지 않기로 해서(§8)
`<Dialogue>` 가 아니라 `<dialogue>` 로 쓰고, 배열 prop은 JSON 문자열로 넘긴다. HTML
파서를 거치므로 self-closing(`<metrics />`)도 통하지 않는다. 실제 문법과 복붙 예제는
`.claude/skills/blog-components/SKILL.md`.

## 8. 채택하지 않은 것 — 콘텐츠 아키텍처

초안의 콘텐츠 아키텍처 절은 **통째로 폐기됐다.** 계획은 이랬다:

- 로더를 velite 또는 contentlayer 계열로 바꿔 `.md`/`.mdx` 혼용을 지원하고, 새 글부터 `.mdx`
- frontmatter 스키마는 `title, date, description, series?, order?, tags[]`
- 다이어그램은 글별 SVG 컴포넌트를 MDX에서 `<DeployPipeline />` 형태로 삽입

하나도 반영되지 않았다. 로더는 `gray-matter` + `react-markdown` + `rehype-raw` 그대로이고,
커스텀 태그는 raw HTML로 처리한다(§7). 루트 `AGENTS.md` 가 "MDX/velite/contentlayer는
아니다"로 못박고 있다.

frontmatter 스키마도 다르다. 실제 필수 키는 `status` · `title` · `date` 이고(`status` 가
없으면 아예 포스트로 취급하지 않는다), `series` 는 frontmatter가 아니라 **폴더 경로**로
정해진다. 전체 목록은 `packages/@blog/content/src/post/frontmatterSchema.ts` 의 서술자
테이블에 있다.
