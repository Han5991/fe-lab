# 블로그 리뉴얼 — 결정 기록

이 문서는 **왜 그렇게 정했는지**만 답한다. 리뉴얼(2026-07~08)에서 무엇을 고르고 무엇을
버렸는지, 그리고 만들면서 그 결정이 어디서 바뀌었는지의 기록이다.

**지금 유효한 규칙과 수치는 여기 없다.** 이 문서의 값을 근거로 코드를 고치지 말 것 —
반대 방향이 맞다. 현행 단일 출처는 다음과 같다:

| 무엇                      | 어디                                         |
| :------------------------ | :------------------------------------------- |
| 색·크기·라운드 등 토큰    | `packages/@blog/preset/src/blog-preset.ts`   |
| 디자인 시스템 수치와 근거 | `.claude/skills/blog-design-system/SKILL.md` |
| 디자인 금지선             | `AGENTS.md` 의 "Blog — design guardrails" 절 |
| 마크다운 커스텀 태그      | `.claude/skills/blog-components/SKILL.md`    |
| 다이어그램 저작법         | `.claude/skills/blog-diagrams/SKILL.md`      |

출처는 claude.ai 디자인 세션의 착수 초안이다. 초안을 그대로 두면 읽는 사람이 폐기된
수치를 먼저 읽게 되므로, **결정과 정착 결과를 한 문단에 합쳐** 다시 적었다.

## 1. 어떤 블로그를 만들려던 것인가

blog.sangwook.dev — 개인 프론트엔드 블로그다. 글은 디자인 시스템, 모노레포/Turborepo,
CI/CD·인프라(ECS, Docker), TypeScript 설계, 오픈소스 기여기가 대부분이고, 형태에 공통점이
있다: 대화체 도입부, 문제→시도→실패→해결의 전개, 수치로 끝맺는 결론(408ms→107ms 같은),
구조 그림 다용, 시리즈 연재. 리뉴얼은 **이 형태를 화면이 받아주게** 만드는 일이었다.
시그니처 컴포넌트 셋(§7)이 여기서 나왔다.

velog(@rewq5991) 크로스포스팅은 당시 하고 있었으나 **접었다.** 히어로의 velog pill과
GA 추적 코드를 함께 걷어냈다.

## 2. 확정한 컨셉

두 갈래의 하이브리드로 갔다.

1. **오픈소스 엔지니어 허브** (레퍼런스: antfu.me) — 글 + 오픈소스 기여 + 발표가 한

2. **다이어그램 아이덴티티** (레퍼런스: blog.maximeheckel.com) — 구조 그림이 썸네일이자
   본문 히어로다.

**하지 않기로 한 것**: 화려한 인터랙션 위젯(Josh Comeau식), 캐릭터·일러스트, 세리프
에세이 톤. 이 셋은 지금도 금지선으로 `AGENTS.md` 에 남아 있다.

**2026-10: 홈에서는 두 갈래 모두 물러났다.** 홈 글 목록이 텍스트 리스트에서 썸네일 카드로 바뀌었고,
다이어그램 썸네일은 지웠다(§7 홈). 다이어그램은 글 히어로·본문에만 남았다.

그 밖의 레퍼런스: ishadeed.com(인라인 데모).

## 3. 타이포그래피

본문·UI는 Pretendard(variable), 날짜·수치·태그·코드는 JetBrains Mono. 갈라놓은 이유는
"측정하는 엔지니어" 무드가 이 블로그 글의 성격이라서다 — 숫자가 sans로 나오면 그 무드가
사라진다.

다만 **숫자가 있다고 기계적으로 mono를 쓰지는 않는다.** 시리즈 배지
(`시리즈 · 번들러 만들기 2/5`)는 안에 숫자가 있어도 본문 성격의 라벨이라 sans로 뒀다.

**2026-10: 크기는 역할 이름(textStyles)으로 고른다.** 자리마다 `fontSize`와 `lineHeight`를 따로 적던
것을 Astryx 코어 타이포 스케일의 역할 이름(`display1`·`h1`·`body`·`label`·`supporting` …) 하나로 묶었다.
값은 승인 목업의 수치를 그대로 썼고, 한 PR(셸)에서 열셋을 한꺼번에 정의했다 — 홈·글 목록·글 상세 PR이
층마다 프리셋을 고치면 스택이 서로 부딪힌다. 쓰지 않는 역할은 CSS로 나가지 않아 무게가 없다. 자간은
두지 않았다(Astryx는 normal이고, 한글에 음수 자간을 주면 받침이 붙는다). mono·sans 구분(위)은 그대로다
— 목업의 날짜·태그가 sans인 건 Astryx 테마에 mono가 연결되지 않은 부작용이라 따르지 않았다.

## 4. 컬러 — 무채색, 포인트색은 잉크

처음엔 무채색 베이스에 포인트 한 색을 따로 골라 썼다(2026-10에 잉크로 옮기며 따로 고른 색은 없어졌다 —
아래). 무채색 값은 초안 그대로 정착했다.

**포인트색은 틸에서 cyan으로 바꿨다.** 두 가지 이유다 — 다크 모드에서는 더 밝은 톤이라야
읽히고, 틸은 success 그린과 색상각이 가까워 의미색과 헷갈렸다.

또 하나, 포인트색은 한 값이 아니라 **용도별 세 단계**로 갈렸다: 선·아이콘용, 링크·배지용
(글자 대비가 WCAG AA를 넘어야 한다), 제목용. 토큰으로는 여기에 틴트·보더·hover가 붙어
여섯 단계(`accent.50`~`accent.900`)였다.

쓰는 자리도 초안보다 넓었다. 초안은 "링크·시리즈 배지·다이어그램 핵심 경로"였는데 한때는
**제목 계열**(홈·About 이름, 대표글 제목, 글 제목, 본문 h1·h2)까지 포함했다. 대신 섹션
라벨·목록 제목·본문 h3·h4는 무채색으로 남겼다.

**2026-10: 포인트색을 본문 잉크로 옮겼다.** Astryx docsite 테마(MIT)를 들이며 그 테마의 구조 —
accent 토큰 전부가 그 테마의 primary 텍스트 잉크다 — 를 따랐다. 따로 고른 색이 없어지니 링크·현재
위치는 밑줄·굵기·틴트로 가른다. 위의 "포인트 한 색"·"용도별 세 단계"·"제목 계열에 색" 결정은 이때 폐기됐다 —
제목은 본문 잉크이고 크기로 갈린다. cyan은 OG 카드의 브랜드 색으로만 남았다(카드 디자인은 바꾸지
않았고, 그 카드가 썸네일인 글은 홈·목록에서 여전히 cyan이 보인다). 현재 값과 구분 수단은
`blog-preset.ts`의 `accent.*` 주석과 `blog-design-system` 스킬에 있다.

## 5. 라운드·보더 — 위계는 보더로만

카드 12px / 작은 요소 8px. **배지는 pill이 아니라 6px로 정착**했다.

**2026-10: 라운드 스케일을 Astryx docsite 테마(MIT)의 것으로 바꿨다.** 이름이 크기(`sm`·`md`)나
한 용도(`card`·`control`)가 아니라 자리(`inner`·`element`·`container`·`page`·`full`)라서, 새
요소는 이름만 보고 값을 고른다. 카드는 12px에서 16px로 커졌고 버튼·배지는 pill이 됐다 — 위의
"배지 6px" 정착은 이때 폐기됐다.

보더는 hairline 하나다. 초안은 "0.5~1px"이라는 범위였는데 폭이 갈리면 같은 화면에 두
굵기가 섞이므로 **1px 단일값**(`borderWidths.hairline`)으로 고정했다.

그림자 대신 보더로 위계를 표현하고 **그라데이션·글로우·장식 효과는 금지**다. 지면 위 요소에서는
이건 지금도 그대로 지켜진다.

**2026-10: 그림자를 떠 있는 표면에만 들였다.** 흐름 밖에 떠서 아래를 가리고 닫히면 사라지는
면(다이얼로그·바텀시트·차트 툴팁)은 Astryx 코어의 그림자 두 단계를 쓴다 — 지면 위 카드·버튼·hover는
여전히 보더뿐이다. 본문 raw HTML용 형광펜 클래스(하드스톱 그라데이션)는 쓰는 글이 없어 이때 지웠다.

## 6. 다이어그램

이미지가 아니라 **SVG React 컴포넌트**로 그린다. 다크모드 색 전환이 자동으로 따라오고,
좁은 화면에서 줄어들고, 글자가 검색되기 때문이다.

문법은 회색(구조) + 액센트(핵심 경로) **2색뿐**, 실선 = 동기 호출 / 점선 = 비동기·데이터
흐름, 부제는 5단어 이내, 노드는 라운드 사각형 `rx=8` 에 스트로크 1px.

**라벨 크기는 의도가 14px + 12px였는데 12px + 11px로 정착했다.** 640px 폭 안에 노드
서넛이 들어가야 해서다. 단일 출처는 `apps/blog/web/src/components/diagram/layout.ts` 의
`TITLE_FONT_SIZE` / `DESC_FONT_SIZE`.

강조 노드를 고르는 prop은 `tone="accent"` 다. 값이 뜻하는 건 색이 아니라 "핵심 경로"라서,
팔레트가 바뀌어도 안 흔들리는 이름으로 바꿨다. 초안 시절 색 이름 `tone="teal"`은 옛 글을 위한
별칭으로 남아 있다가, 원고 사용이 0건이라 2026-10에 지웠다.

저작법 전체(선언형 태그, 레지스트리, `hero:`)는 `.claude/skills/blog-diagrams/SKILL.md`.

## 7. 페이지와 시그니처 컴포넌트

### 홈

네비는 **글 · 시리즈 · About**이다. 초안에는 오픈소스와 발표가 독립 메뉴였는데, 둘 다
About 페이지 안의 섹션으로 들어갔다.

**히어로 우측의 장식 다이어그램은 뺐다.** `aria-hidden` 장식이라 정보가 0인데, 정작
다이어그램이 뜻을 갖는 자리(글 히어로·본문)와 언어가 겹쳐 그쪽 무게를 깎았다. 다이어그램은
글 안에서만 쓴다. 바깥 채널도 GitHub / RSS 둘뿐이다(velog 제외 — §1).

하단 오픈소스 스트립의 칩은 4개(node.js / next.js / gemini-cli / mantine)이고, merged 수는
빌드 타임에 주입된다(`NEXT_PUBLIC_PR_COUNT`, 폴백 58).

**2026-10: 홈을 텍스트 허브에서 썸네일 카드로 바꿨다**(승인 목업 — Astryx docsite의 BlogShowcase).
§2의 "글 목록은 장식 없는 텍스트 리스트" 결정과, 대표 글 카드 한 장 + 제목·날짜 12줄이던 홈이 이때
폐기됐다. 결정과 이유:

- **최근 글 셋은 카드로, 그다음 여덟 편은 썸네일 행으로 보인다.** 텍스트 리스트는 글이 무엇을
  다루는지 제목 한 줄로만 말했는데, 이 블로그 글의 썸네일은 대부분 수치·구조를 그린 카드라 그 자체가
  내용 요약이다. 홈의 글 목록 링크는 13개(대표 1 + 12줄)에서 11개로 줄었다 — 나머지는 "N편 모두
  보기"가 맡는다.
- **다이어그램 썸네일(ParallelThumb)을 지웠다.** 대표 글의 썸네일이 없거나 생성 OG 카드면 같은
  "병렬 처리" 그림을 세우던 폴백이라, 어떤 글이 와도 같은 그림이었다. 카드는 이제 썸네일이 없으면 그 글의 생성 OG 카드를
  쓴다 — 글마다 제목이 박힌 그림이다.
- **카드는 링크 하나다.** 목업은 커버와 제목에 링크를 따로 걸었다. 같은 곳 링크가 둘이면 탭을 두 번
  누르고 스크린리더가 두 번 읽어서, 제목 링크가 카드 전체를 덮게 했다.
- **쇼케이스 커버는 16:9로 고정했다.** 목업은 옆 열 높이를 따라 늘어 약 3:2였는데, 그러면 OG 카드의
  좌우가 127px씩 잘려 글자가 날아가고 이미지 도착 전후로 높이가 달라질 여지가 생긴다. 16:9면 40px씩이다.
- **날짜·읽기 시간·태그는 mono로 남겼다**(§3). 카드의 읽기 시간 표기는 `N min`(대표 글 카드)·`N분`
  (목록 그리드)이 섞여 있던 것을 `fmtReadMin`(`N분`) 하나로 모았다. 글 상세 머리(`PostHeader`)는 아직
  `N min`이다.
- **히어로의 바깥 채널은 셸의 목록을 버튼으로 그린다.** 히어로가 따로 들고 있던 소셜 pill 목록을 지우고,
  헤더·푸터 아이콘과 같은 `SOCIAL_LINKS`를 글자 버튼(GitHub neutral · RSS ghost)으로 그린다 — 목록은
  하나이고 히어로가 정하는 건 모양뿐이다.
- **시리즈 배지를 홈에서 뺐다.** 대표 글 카드만 달던 배지라, 카드가 셋이 되며 한 장에만 붙일 이유가
  없어졌다. 시리즈 소속은 글 상세와 `/series`가 보여 준다.

### 글 목록

**2026-10: 글 목록(`/posts`)을 사이드바 두 칼럼에서 752 단일 칼럼으로 바꿨다**(승인 목업 — Astryx
docsite의 BlogIndex). 위에서부터 제목 묶음(가운데 정렬 `display1` + 사이트 소개), 검색, 시리즈 칩, 툴바
("N편" · 정렬 · 보기), 적용된 태그 필터, 피처 카드, 카드 그리드(또는 행 목록)다. 결정과 이유:

- **태그·연도 필터 UI, 모바일 필터 시트와 그 FAB, 인기 글 레일을 걷었다.** 태그 필터는 글 상세의 태그
  링크(`?tag=`)로만 들어오고 화면에는 걸린 태그를 푸는 버튼만 남는다. 인기 글은 정렬의 "인기순"이
  대신한다. 시트가 쓰던 `motion`은 이제 블로그 어디서도 쓰지 않는다.
- **컨트롤은 네이티브다.** 정렬은 `<select>`, 시리즈 칩과 보기 토글은 `<input type="radio">` 묶음이다.
  옵션 목록·화살표 이동·초점 이동을 브라우저가 해서 roving tabindex JS가 없어졌다. 시리즈 칩은 Tab
  정지점이 하나다(목업은 `aria-pressed` 버튼 여럿). 켜짐·hover·초점 링·강제 색상은
  `label > input.peer + span` 구조의 **형제 선택자**로 냈다 — `:has()`는 Next 기본 대상의 Firefox
  111~120에 없어서 쓰지 않는다. 검색 "지우기"는 `:placeholder-shown` 형제 선택자가 숨긴다. 칩·칸은 켜질
  때 semibold가 되어도 폭이 그대로다(숨긴 semibold 사본을 겹치는 `SteadyLabel`, Astryx ToggleButton
  동작).
- **보기 토글의 켜진 면은 고른 칸으로 미끄러진다**(fast·standard, transform만이라 합성된다). 면 하나가
  움직이려면 칸 폭이 같아야 해서 '카드' 칸이 '리스트' 칸 폭으로 넓어졌다(목업은 글자 폭). 위치는 고른
  칸의 순서를 트랙의 style 변수로 내보내 CSS가 계산한다 — 새 훅이 없고, 정적 HTML에도 실려 기본 보기는
  하드 로드 첫 페인트부터 제자리다. `?view=list`로 들어오면 아래 하드 로드 항목대로 기본 상태가 잠깐
  보인 뒤 면은 미끄러지지 않고 리스트 칸에 바로 놓인다 — 정적 HTML은 Suspense 폴백이라 클라이언트가
  컨트롤을 새 요소로 그려 전환이 없다. 강제 색상 모드는 면을 지우므로 켜진 칸의 밑줄이 그대로 선택을

- **상태는 로컬이 진실이고 URL은 뒤따라 쓴다**(`nuqs` 대신). 컨트롤은 로컬 상태로 제어하고 URL은

### 목록 → 글 상세 전환

**2026-10: 카드의 커버와 제목이 글 상세로 이어진다**(ssgoi hero의 모양을 라이브러리 없이). 그 전의
ssgoi 설정은 `/posts` ↔ 썸네일 있는 글 상세만 모핑하고 나머지는 페이드였고, 페이지 전환을 React
`<ViewTransition>`으로 옮기며(같은 달) 모핑이 한동안 빠져 있었다. 결정과 이유:

- **짝은 커버와 제목 둘이다.** 커버 ↔ 상세 히어로 이미지, 제목 ↔ 상세 h1. 홈 카드·썸네일 행·
  `/posts` 카드·글 목록 행(`/posts` 목록 보기와 `/series`, 제목만)이 모두 짝을 단다 — ssgoi 때는
  `/posts`만이었다. 목록 행은 두 화면이 같은 마크업을 따로 들고 있던 것을 `PostListRow` 하나로
  합쳤다. 다이어그램 히어로는 카드에 없는 그림이라 짝을 만들지 않는다.
- **짝이 되는 이동을 둘로 한정했다** — 카드를 눌러 열 때와, 그 글의 상세에서 링크로 목록에 돌아갈
  때. 이름만 맞추면 홈 → `/posts`처럼 같은 글이 양쪽에 있는 목록 → 목록 이동에서도 카드끼리 짝이
  돼 열네 개가 한꺼번에 날아다녔다(실측). ssgoi가 경로 쌍으로 막던 것을 링크의 transition type과
  "열린 글"로 막는다.
- **커버는 상세 쪽 스냅샷이 바닥이다.** 카드는 원본의 가운데를 잘라 보이고 상세는 원본 비율이라,
  기본 크로스페이드는 서로 다른 부분이 겹쳐 두 겹으로 보였고, 두 장을 함께 흐리게 하면 가장자리에
  밝은 띠가 생겼다. 상세 스냅샷을 cover로 채워 불투명하게 두고 카드 스냅샷만 contain으로 맞춰
  위에서 흐리게 했다. 같은 이유로 상세 히어로가 원본 PNG 대신 카드와 같은 최적화본 webp를 띄운다
  (OG·JSON-LD는 PNG 그대로) — 카드에서 넘어오면 이미 받은 이미지라 전환이 이미지를 기다리지 않는다.
- **카드 커버의 hairline을 이미지 위로 옮겼다.** 틀의 보더가 이미지를 1px 안으로 밀어, 두 스냅샷이
  최대 4px 어긋나 이미지 속 글자가 두 겹으로 보였다. 선을 이미지 위에 덮어 그리자 어긋남이 0~0.5px
  (리샘플링 오차)로 줄었다. 어두운 이미지에서는 선이 이미지 가장자리에 묻혀 거의 보이지 않고, 밝은
  이미지는 예전처럼 지면과 갈린다. 바닥 스냅샷은 cover로 잘리며 상세 히어로의 라운드도 잘려 첫
  프레임부터 모서리가 각졌는데, 모서리를 그룹 상자에 다시 깎아(카드 쪽 `container` ↔ 상세 쪽
  `element`) 고쳤다.
- **제목은 늘이지 않는다.** 카드 제목(14~24px, 좁은 칼럼)과 h1(22px)은 크기도 줄바꿈도 달라 스냅샷을
  늘이면 글자가 뭉갰다. 자리만 옮기고 글자는 순서대로 바꾼다. 처음 판은 제목을 커버 위에 그려 다크에서
  흰 글자가 날아가는 커버 그림 위를 지나갔고, 줄어드는 그룹 밖으로 h1 끝이 옆 카드 위를 지나갔다 —
  제목을 커버 아래에 쌓고, 그룹 상자 밖을 자르고, 나가는 제목을 감속 곡선으로 처음에 걷는다.
- **브라우저 뒤로 가기에는 모핑이 없다(보류).** Next는 popstate를 transition으로 넘기지만 React가
  스크롤 복원을 위해 그 자리에서 동기로 커밋해 View Transition이 열리지 않는다. 프레임워크가 여는
  길이 없어 우회는 넣지 않았다 — 링크로 돌아가는 이동만 거꾸로 모핑한다.

### 이동의 방향

**2026-10: 링크 이동이 앱의 계층에서 깊이 들어가면 왼쪽으로, 돌아오면 오른쪽으로 미끄러진다**(Next
view-transitions 가이드의 directional motion). 그 전에는 모든 이동이 제자리 페이드였다 — 브라우저 뒤로
가기에는 전환이 없어 방향을 넣어도 링크 이동에서만 보인다는 이유로 미뤘는데, 공유 요소 짝이 없는 이동에도
"앱 느낌"을 주려고 링크 이동만이라도 넣었다. 뒤로 가기는 지금도 전환이 없다. 결정과 이유:

- **방향은 링크가 아니라 이동의 성질이다.** 홈 0 · 섹션 1 · 글 2의 깊이로 출발·도착을 비교해 정하고,
  같은 깊이는 형제 순서(이전·다음 글)가 있을 때만 정한다. 규칙은 한 함수이고 링크는 그 결과를 받는
  감싸개(`TransitionLink`)를 쓴다 — 링크마다 type을 손으로 달면 같은 이동(홈 → `/posts`)이 헤더로 가면
  밀리고 "더 보기"로 가면 페이드하는 식으로 갈린다. 깊이가 순서보다 먼저라 시리즈 마지막 편의
  "시리즈 목록 →"은 오른쪽 자리여도 위로 가는 이동이다(그 카드는 형제가 아니라 순서를 주지 않는다).
- **`next/link`를 바로 여는 것은 lint로 막았다.** 빠뜨린 링크는 깨지지 않고 그 이동만 페이드로 남아
  어디서도 드러나지 않는다 — 위의 "같은 이동이 링크마다 갈림"이 조용히 다시 열린다. 허용은 방향을
  일부러 달지 않는 곳(검색 다이얼로그, 에러 경계가 그리는 `ErrorFallback`, admin)만 사유와 함께
  설정에 적었다. 재평가 2027-04-24.
- **헤더 형제(`/posts` ↔ `/series` ↔ `/about`)와 검색 결과는 페이드로 남겼다.** 형제는 위아래가 없고,
  검색은 모달을 닫으며 가는 이동이라(깊이와 상관없이) 페이지가 옆으로 밀리면 닫히는 패널과 엇갈린다.
- **카드로 글을 열 때도 방향을 단다.** 공유 요소 모핑과 슬라이드가 싸울지 보려고 같은 이동을 페이드로
  바꿔 프레임을 비교했는데, 페이드 쪽이 새 글의 본문이 나가는 목록 위에 겹쳐 보여 더 어지러웠다.
- **나감과 들어옴을 겹치지 않는다 — 자리까지.** 나가는 페이지가 먼저 걷히고(fast·exit) 들어오는 페이지가
  그 뒤에 들어온다(fast 지연·fastMax·standard). 가이드도 투명도는 순서대로 두지만(나가는 내용이 시선을
  다투지 않게) 슬라이드는 양쪽을 0ms부터 400ms 동안 함께 돌린다. 여기서는 들어오는 쪽의 슬라이드도
  지연했다 — standard는 앞에 몰린 곡선이라 처음부터 돌리면 보일 때 이미 거리의 대부분을 와 있어 방향이
  안 보이고, 같은 쪽으로 미끄러지는 두 페이지의 글자가 겹쳐 보인다. 거리는 32px — 가이드의 60px보다
  짧지만 들어오는 쪽이 지연 뒤에 출발해 거리 전부가 보인다.
- **글 하단 이전·다음 카드를 페이지 전환 경계 안에 넣었다.** 경계 밖에 있던 카드는 React가 루트 스냅샷을
  투명하게 두는 이동에서 전환 첫 프레임에 사라져, 누른 카드가 슬라이드 전에 먼저 없어졌다.
- **404·admin도 경계에 담았다.** 경계가 없던 화면에서 방향 있는 이동으로 떠나면 그 화면은 첫 프레임에
  사라지고 들어오는 페이지는 fast 뒤에 나타나, 헤더만 남은 빈 지면이 175ms 보였다(404 → 헤더 '글' 실측 —
  방향이 없던 때는 들어오는 페이지가 0ms부터 떠올라 드러나지 않았다). admin은 페이지마다가 아니라 영역
  전체를 서버 레이아웃의 경계 하나에 담아, 영역을 드나드는 이동만 움직이고 admin 안의 이동은 전처럼
  움직이지 않는다. 에러 경계(`error.tsx`)는 뺐다 — 클라이언트 컴포넌트라 경계를 두면 그 코드와
  `VIEW_TRANSITION` 그룹 객체가 모든 페이지의 첫 로드에 실렸다(실측 +314B gzip). 드문 에러 화면을 떠날
  때의 빈 지면과 바꾸지 않았다. admin도 처음엔 클라이언트 레이아웃에 뒀다가 같은 이유(공유 모듈을 거쳐
  공개 페이지 +128B)로 서버 레이아웃으로 옮겼다.

### 시그니처 컴포넌트 셋

`<dialogue>`(도입부 대화 재현) · `<metrics>`(before/after 수치) · `<timeline>`(시도1 실패 →
시도2 실패 → 시도3 성공). §1에 적은 글의 형태를 그대로 받는 세 개다.

**MDX 컴포넌트가 아니라 소문자 raw HTML 커스텀 태그다.** MDX를 도입하지 않기로 해서(§8)
`<Dialogue>` 가 아니라 `<dialogue>` 로 쓰고, 배열 prop은 JSON 문자열로 넘긴다. HTML
파서를 거치므로 self-closing(`<metrics />`)도 통하지 않는다. 실제 문법과 복붙 예제는
`.claude/skills/blog-components/SKILL.md`.

## 8. 채택하지 않은 것 — 콘텐츠 아키텍처

초안의 콘텐츠 아키텍처 절은 **통째로 폐기됐다.** 계획은 이랬다:

- 로더를 velite 또는 contentlayer 계열로 바꿔 `.md`/`.mdx` 혼용을 지원하고, 새 글부터 `.mdx`
- frontmatter 스키마는 `title, date, description, series?, order?, tags[]`
- 다이어그램은 글별 SVG 컴포넌트를 MDX에서 `<DeployPipeline />` 형태로 삽입

하나도 반영되지 않았다. 로더는 `gray-matter` + `react-markdown` + `rehype-raw` 그대로이고,
커스텀 태그는 raw HTML로 처리한다(§7). 루트 `AGENTS.md` 가 "MDX/velite/contentlayer는
아니다"로 못박고 있다.

frontmatter 스키마도 다르다. 실제 필수 키는 `status` · `title` · `date` 이고(`status` 가
없으면 아예 포스트로 취급하지 않는다), `series` 는 frontmatter가 아니라 **폴더 경로**로
정해진다. 전체 목록은 `packages/@blog/content/src/post/frontmatterSchema.ts` 의 서술자
테이블에 있다.
