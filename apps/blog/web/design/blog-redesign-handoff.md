# 블로그 리뉴얼 핸드오프 (claude.ai 세션 → Claude Code)

> 이 문서는 claude.ai에서 진행한 디자인 세션의 결과물이다.
> 이 문서를 읽었다면, 아래 "작업 순서"의 1번부터 진행한다.
> 결정된 사항은 임의로 변경하지 말고, 모호한 부분만 질문한다.

## 1. 프로젝트 컨텍스트

- 대상: 한상욱의 개인 프론트엔드 개발 블로그 (blog.sangwook.dev) 리뉴얼
- 현재 상태: 기존 개인 블로그 운영 중, velog(@rewq5991)에는 요약+링크로 크로스포스팅
- 글 성격: 디자인 시스템, 모노레포/Turborepo, CI/CD·인프라(ECS, Docker), TypeScript 설계, 오픈소스 기여기
- 글 특징: 대화체 후킹 도입부(기획자/PM과의 대화), 문제→시도→실패→해결 서사, 수치 성과 강조(예: 408ms→107ms, 74% 개선), 아키텍처 다이어그램 다용, 시리즈 연재 다수

## 2. 확정된 디자인 컨셉

두 컨셉의 하이브리드로 확정:

1. **오픈소스 엔지니어 허브** (레퍼런스: antfu.me)
   - 글 + 오픈소스 기여 + 발표가 한 사이트에 병렬로 존재
   - 글 목록은 장식 없는 텍스트 리스트 (제목 + 날짜)
2. **다이어그램 아이덴티티** (레퍼런스: blog.maximeheckel.com)
   - 아키텍처 다이어그램이 썸네일이자 본문 히어로
   - 모든 다이어그램은 아래 "다이어그램 문법"으로 통일

하지 않기로 한 것: 화려한 인터랙션 위젯(Josh Comeau식), 귀여운 캐릭터/일러스트, 세리프 에세이 톤.

## 3. 디자인 토큰

### 타이포그래피

- 본문/UI: Pretendard (variable)
- 날짜·수치·태그·코드: JetBrains Mono
- 규칙: 숫자와 메타 정보는 반드시 모노스페이스로. "측정하는 엔지니어" 무드의 핵심.

### 컬러

- 무채색 베이스 + 포인트 1색(틸 계열)만 사용
- 라이트: 배경 #FFFFFF / 서브 배경 #F7F7F5 / 본문 #1A1A1A / 보조 텍스트 #6B7280 / 포인트 #1D9E75
- 다크: 배경 #0B0D10 / 서브 배경 #14171C / 본문 #E6E8EB / 보조 텍스트 #8B919A / 포인트 #5DCAA5
- 포인트색은 링크, 시리즈 배지, 다이어그램의 "핵심 경로"에만 사용. 남용 금지.

### 기타

- 라운드: 카드 12px, 작은 요소 8px, 배지 pill
- 보더: 0.5~1px hairline, 그림자 대신 보더로 위계 표현
- 그라데이션·글로우·장식 효과 금지 (플랫 유지)

## 4. 다이어그램 문법 (모든 글 공통)

- 노드: 라운드 사각형(rx 8px), 스트로크 0.5~1px
- 선: 실선 = 동기 호출, 점선 = 비동기/데이터 흐름
- 색: 회색(구조) + 틸(핵심 경로) 2색만. 강조 노드에만 틸 적용
- 라벨: 노드 제목 14px + 부제 12px, 부제는 5단어 이내
- 구현: 이미지가 아니라 SVG React 컴포넌트로 작성 (다크모드 색 전환 자동화)

## 5. 페이지 사양

### 홈 (허브)

- 상단 네비: 로고(sangwook.dev, 모노스페이스) / 글 · 시리즈 · 오픈소스 · 발표 · 다크모드 토글
- 히어로: 이름 + 두 줄 소개 + 우측에 작은 다이어그램 모티프(장식용 SVG) + github/velog/rss pill 링크
- 대표 글 카드 1개: 시리즈 배지 + 제목 + 한 줄 요약 + 날짜·읽기시간(모노) + 우측 미니 다이어그램 썸네일
- 글 목록: 보더로 구분된 텍스트 리스트 (제목 좌측, 날짜 우측 모노)
- 하단 오픈소스 스트립: node.js / next.js / gemini-cli / mantine / react-hook-form 칩 + "42+ merged" 강조 칩

### 글 상세

- 시리즈 배지 (예: "시리즈 · Turborepo 인프라 3/3") + 제목 + 메타(날짜·읽기시간·태그, 모노)
- 다이어그램 히어로: 글 핵심 구조를 그린 SVG (문법은 4번 준수)
- 본문: 마크다운 렌더링 + 아래 시그니처 컴포넌트 삽입 가능

## 6. 시그니처 MDX 컴포넌트 (3개)

### `<Dialogue>` — 대화 버블

- 용도: 도입부 슬랙/구두 대화 재현
- 구조: `<Dialogue><Msg from="PM">...</Msg><Msg from="me">...</Msg></Dialogue>`
- 스타일: from="me"는 우측 정렬 + 포인트색 배경, 그 외 좌측 + 서브 배경. 아바타는 이니셜 원형(30px)
- 좌측에 2px 세로 보더로 인용 블록 느낌 부여

### `<Metrics>` — 성과 수치 카드

- 용도: before/after 수치 강조
- props: `items: { label: string; value: string; tone?: 'default' | 'success' }[]`
- 스타일: 2~4열 그리드, 서브 배경 카드, 라벨 12px 뮤티드 + 값 20px 모노 500

### `<Timeline>` — 시도 타임라인

- 용도: 시도1 실패 → 시도2 실패 → 시도3 성공 서사
- props: `steps: { title: string; desc: string; result: 'fail' | 'success' }[]`
- 스타일: 좌측 아이콘(실패 = x/red 아웃라인, 성공 = check/green 아웃라인) + 세로 연결선

## 7. 콘텐츠 아키텍처

- 기존 글은 순수 마크다운(.md). MDX로 점진 전환한다:
  - 콘텐츠 로더는 .md와 .mdx 혼용 지원 구성 (velite 또는 contentlayer 계열)
  - 기존 글은 유지, 새 글부터 .mdx
- frontmatter 스키마: `title, date, description, series?, order?, tags[]`
- .md → .mdx 변환 시 주의: HTML 주석(<!-- -->) 제거, 이스케이프 안 된 `<` `{` 문자 수정
- 다이어그램은 글별 SVG 컴포넌트로 작성해 MDX에서 `<DeployPipeline />` 형태로 삽입

## 8. 작업 순서 (이 순서대로 진행)

1. 현재 레포 구조 파악 후 이 문서와 충돌하는 지점 보고
2. 디자인 토큰 세팅 (폰트 로딩 포함, 라이트/다크)
3. 시그니처 컴포넌트 3개 구현 + MDX 렌더러에 등록
4. 글 상세 템플릿 리뉴얼 (시리즈 배지, 히어로 다이어그램 슬롯)
5. 홈(허브) 페이지 리뉴얼
6. 기존 글 1개를 .mdx로 변환해 컴포넌트 적용 예시 만들기 (ECS 배포 글 권장)
7. 시리즈 목록 페이지 (추후 논의)
