# 블로그 리뉴얼 핸드오프 (claude.ai 세션 → Claude Code)

> **이 문서는 착수 시점의 초안이고, 리뉴얼은 끝났다. 지금의 기준은 구현된 코드다.**
>
> claude.ai 디자인 세션에서 나온 결정과 그 배경을 남겨 둔 기록이다. 만들면서
> 바뀐 것이 적지 않고, 아예 채택하지 않은 절도 있다. **여기 적힌 수치나 API를
> 근거로 코드를 고치지 말 것** — 반대 방향이 맞다.
>
> 지금 유효한 규칙은:
>
> | 무엇                      | 어디                                            |
> | :------------------------ | :---------------------------------------------- |
> | 색·크기·라운드 등 토큰    | `packages/@design-system/ui/src/blog-preset.ts` |
> | 디자인 시스템 수치와 근거 | `.claude/skills/blog-design-system/SKILL.md`    |
> | 디자인 금지선             | `CLAUDE.md` 의 "디자인 시스템 · 저작 문법" 절   |
> | 다이어그램 저작법         | `apps/blog/web/design/DIAGRAM_AUTHORING.md`     |
> | 마크다운 커스텀 태그      | `.claude/skills/blog-components/SKILL.md`       |
>
> 각 절 머리의 `⚠️` 는 구현이 이 초안과 다르게 정착한 지점이다.

## 1. 프로젝트 컨텍스트

- 대상: 한상욱의 개인 프론트엔드 개발 블로그 (blog.sangwook.dev) 리뉴얼
- 현재 상태: 기존 개인 블로그 운영 중, velog(@rewq5991)에는 요약+링크로 크로스포스팅
- 글 성격: 디자인 시스템, 모노레포/Turborepo, CI/CD·인프라(ECS, Docker), TypeScript 설계, 오픈소스 기여기
- 글 특징: 대화체 후킹 도입부(기획자/PM과의 대화), 문제→시도→실패→해결 서사, 수치 성과 강조(예: 408ms→107ms, 74% 개선), 아키텍처 다이어그램 다용, 시리즈 연재 다수

> ⚠️ **velog 크로스포스팅은 접었다.** 히어로의 velog pill과 추적 코드
> (`lib/ga-proxy-generator.ts`)를 모두 걷어냈다.

## 3. 디자인 토큰

### 타이포그래피

- 본문/UI: Pretendard (variable)
- 날짜·수치·태그·코드: JetBrains Mono
- 규칙: 숫자와 메타 정보는 반드시 모노스페이스로. "측정하는 엔지니어" 무드의 핵심.

> ⚠️ **시리즈 배지는 예외로 sans다.** `시리즈 · 번들러 만들기 2/5` 처럼 안에
> 숫자가 있어도 본문 성격의 라벨이라, 숫자가 있다고 기계적으로 mono를 적용하지
> 않는다.

### 컬러

- 무채색 베이스 + 포인트 1색(틸 계열)만 사용
- 라이트: 배경 #FFFFFF / 서브 배경 #F7F7F5 / 본문 #1A1A1A / 보조 텍스트 #6B7280 / 포인트 #1D9E75
- 다크: 배경 #0B0D10 / 서브 배경 #14171C / 본문 #E6E8EB / 보조 텍스트 #8B919A / 포인트 #5DCAA5
- 포인트색은 링크, 시리즈 배지, 다이어그램의 "핵심 경로"에만 사용. 남용 금지.

> ⚠️ **포인트색은 틸에서 cyan으로 바뀌었다.** 다크에서 밝은 톤이라야 읽히는데다,
> 틸은 success 그린과 색상각이 가까워 의미색과 헷갈렸다. 무채색 값은 초안 그대로다.
>
> 또 하나, 포인트색은 **한 값이 아니라 용도별 세 단계**로 갈렸다 — 선·아이콘용,
> 링크·배지용(글자 AA), 제목용. 현재 값과 그렇게 나눈 이유는 `blog-preset.ts` 의
> `accent.*` 주석에 있다.
>
> 쓰는 자리도 넓어졌다. 초안은 "링크·배지·다이어그램"이었지만 지금은 **제목 계열**
> (홈·About 이름, 대표글 제목, 글 제목, 본문 h1·h2)까지 포함한다. 대신 섹션 라벨과
> 목록 제목, 본문 h3·h4는 무채색으로 남긴다.

### 기타

- 라운드: 카드 12px, 작은 요소 8px, 배지 pill
- 보더: 0.5~1px hairline, 그림자 대신 보더로 위계 표현
- 그라데이션·글로우·장식 효과 금지 (플랫 유지)

> ⚠️ **배지는 pill이 아니라 6px**이고, **hairline은 0.5~1px 폭이 아니라 1px 단일
> 값**(`borderWidths.hairline`)이다. 그라데이션 금지는 지켜졌다.

## 4. 다이어그램 문법 (모든 글 공통)

- 노드: 라운드 사각형(rx 8px), 스트로크 0.5~1px
- 선: 실선 = 동기 호출, 점선 = 비동기/데이터 흐름
- 색: 회색(구조) + 포인트색(핵심 경로) 2색만. 강조 노드에만 포인트색 적용
- 라벨: 노드 제목 12px + 부제 11px, 부제는 5단어 이내
- 구현: 이미지가 아니라 SVG React 컴포넌트로 작성 (다크모드 색 전환 자동화)

> ⚠️ **라벨 크기는 의도가 14px + 12px였는데 12px + 11px로 정착했다.** 640px 폭
> 안에 노드 서넛이 들어가야 해서다. 단일 출처는 `src/components/diagram/layout.ts`
> 의 `TITLE_FONT_SIZE` / `DESC_FONT_SIZE`.
>
> 스트로크도 hairline 1px 단일이다.
>
> 강조 노드를 고르는 prop은 `tone="accent"`다. 초안 시절 색 이름을 그대로 쓴
> `tone="teal"` 은 옛 글을 위한 별칭으로만 남아 있고, 새 글에는 쓰지 않는다 —
> 값이 뜻하는 건 색이 아니라 "핵심 경로"라서 팔레트에 안 묶이는 이름으로 바꿨다.
>
> 저작법 전체(선언형 태그, 레지스트리, `hero:`)는 `DIAGRAM_AUTHORING.md` 에 있다.

## 6. 시그니처 컴포넌트 (3개)

> ⚠️ **MDX 컴포넌트가 아니라 소문자 raw HTML 커스텀 태그다.** MDX를 도입하지
> 않기로 해서(§7 참고) `<Dialogue>` 가 아니라 `<dialogue>` 로 쓰고, 배열 prop은
> JSON 문자열로 넘긴다. HTML 파서를 거치므로 self-closing(`<metrics />`)도 안 된다.
> 실제 문법과 복붙 예제는 `.claude/skills/blog-components/SKILL.md` 에 있다.

### `<Dialogue>` — 대화 버블

- 용도: 도입부 슬랙/구두 대화 재현
- 구조: `<Dialogue><Msg from="PM">...</Msg><Msg from="me">...</Msg></Dialogue>`
- 스타일: from="me"는 우측 정렬 + 포인트색 배경, 그 외 좌측 + 서브 배경. 아바타는 이니셜 원형(30px)
- 좌측에 2px 세로 보더로 인용 블록 느낌 부여

### `<Metrics>` — 성과 수치 카드

- 용도: before/after 수치 강조
- props: `items: { label: string; value: string; tone?: 'default' | 'success' }[]`
- 스타일: 2~4열 그리드, 서브 배경 카드, 라벨 12px 뮤티드 + 값 20px 모노 500

> ⚠️ 값은 20px이 아니라 19px이고, `items` 는 JSON **문자열**로 넘긴다.

### `<Timeline>` — 시도 타임라인

- 용도: 시도1 실패 → 시도2 실패 → 시도3 성공 서사
- props: `steps: { title: string; desc: string; result: 'fail' | 'success' }[]`
- 스타일: 좌측 아이콘(실패 = x/red 아웃라인, 성공 = check/green 아웃라인) + 세로 연결선

## 7. 콘텐츠 아키텍처 — **채택하지 않음**

> ⚠️ **이 절은 통째로 폐기됐다.** 아래 계획은 하나도 반영되지 않았으니 근거로 쓰지 말 것.
>
> velite/contentlayer도, MDX 전환도 하지 않았다. 로더는 `gray-matter` +
> `react-markdown` + `rehype-raw` 그대로이고, 커스텀 태그는 raw HTML로 처리한다
> (§6 참고). 루트 `AGENTS.md`가 "MDX/velite/contentlayer는 아니다"로 못박고 있다.
>
> frontmatter 스키마도 다르다. 실제 키는 `status` · `title` · `date` 를 필수로 하고
> (`status` 가 없으면 아예 포스트로 취급하지 않는다), `series` 는 frontmatter가
> 아니라 **폴더 경로**로 정해진다. 전체 목록은 CLAUDE.md의 frontmatter 표와
> `@blog/content`(`src/post/frontmatterSchema.ts`)의 서술자 테이블 — `RawFrontmatter`
> 타입이 거기서 파생된다 — 에 있다.

<details>
<summary>원래 계획 (기록용)</summary>

- 기존 글은 순수 마크다운(.md). MDX로 점진 전환한다:
  - 콘텐츠 로더는 .md와 .mdx 혼용 지원 구성 (velite 또는 contentlayer 계열)
  - 기존 글은 유지, 새 글부터 .mdx
- frontmatter 스키마: `title, date, description, series?, order?, tags[]`
- .md → .mdx 변환 시 주의: HTML 주석(<!-- -->) 제거, 이스케이프 안 된 `<` `{` 문자 수정
- 다이어그램은 글별 SVG 컴포넌트로 작성해 MDX에서 `<DeployPipeline />` 형태로 삽입

</details>
